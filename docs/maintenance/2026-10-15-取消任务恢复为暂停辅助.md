# 取消任务恢复为暂停辅助

用户明确误取消本批任务，需要恢复，且不能自动上架。本分包仅准备纯 helper 与3条基础测试，不写真实数据库，不接入服务、IPC或界面。实际只选哪一个任务由主进程在新程序界面确认；产品无需硬编码真实任务 ID。

`planCancelledTaskRecovery` 核对所选 taskId、expectedRevision、CANCELLED 状态以及 owner 提供的无 worker/确认/归档/准备活动条件。返回补丁只有 `status: PAUSED`，不改变原 error、items、SKU、子任务引用、费用、次数、round、UNKNOWN，也不产生调度许可；revision 与 updatedAt 由服务原有 header-only CAS 保存递增。

服务 owner 的接线建议（本分包未修改公共 service.ts）：

```ts
// 在确认对话框之后再次按原 taskId/revision 读取，并在同一同步事务内：
const before = this.task(input.taskId);
this.assertManaged(before.id);
const plan = planCancelledTaskRecovery(before, input, {
  workerActive: !!this.worker || !!this.observing || this.activeId !== null,
  confirming: this.confirming.size > 0,
  archiving: this.archiving,
  preparing: !!this.operationProgress,
});
const next = { ...before, ...plan.patch }; // items 引用及内容均保持
// transaction(this.db, () => { ... }) 包住下面的 header CAS 与审计：
this.save(next, this.db, [], undefined, []);
appendAuditEvent(this.db, randomUUID(), null, plan.audit.action,
  plan.audit.summary, JSON.stringify(plan.audit.detail), next.updatedAt);
// 成功提交后才 this.tasks.set(next.id, next)。
// 外层审计/事务失败时按原 owner 模式恢复 before 的 checkpoint proof，
// 不让已回滚的 revision 留在内存校验证明中。
```

不得调用 start/queue、grants.add、activateQueuedTask、stopChildren、远端取消或恢复、轮次重置。归档中的任务不能凭该 helper 新建工作批次或复制成新任务；目标是恢复原任务的本地暂停状态。主进程需补 service 接线的事务/CAS及审计验证。
