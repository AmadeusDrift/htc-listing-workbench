# 首次妙手事实入库的有限来源属性规范化

分支：`fix/source-attribute-normalization`。基线：`1bb06dbd16f7facb6421a9d60ad617448ce6205c`（字段规范化分支合并）。当前证据仍为 `listing-evidence/v3`，冻结证据实现、stored 派发、已有事实和历史上下文不迁移。

本轮实现者只使用本地合成来源、演示 Schema、隔离数据库与加密备份。父任务负责独立 SPEC/QUALITY 审查、最终全量验证、维护总表及 Git 提交合并；实现者没有执行 Git 写操作、全量测试、真实 AI/Amazon/妙手网络调用、打印、发布、push 或覆盖 release。

## 实际缺口与 RED

妙手 `persistImport` 在首次创建 product facts 时原样使用 `snapshot.attributes`。来源 `ｍａｔｅｒｉａｌ=Ｓｉｌｉｃｏｎｅ` 既不能直接映射，也不能成为正确类型的材质证据；已知年龄属性的 `Ａｄｕｌｔ` 被当前分类和文案证据拒绝。`产品长度=2 in`、`2 centimeters` 能进入 Amazon 测量映射，但其来源文字不能支持当前冻结 typed evidence 的 `2 inches`、`2 cm` 文案。因此仅修 mapper 不足以修复本入口。

正式 `tests/source-attribute-normalization.test.ts` 首轮 12 tests / 1 pass / 11 fail，943.2902 ms。9 项业务断言失败直接显示首次入库仍保存全角值或原单位别名；另有 trace 不存在断言失败，1 项后续 `entries` 访问因缺 trace 抛 TypeError，随后补显式存在断言；unknown/model/裸数原值保护正控通过。最小实现后 12/12 通过。过程中材质正控曾误引用所有不同类型证据，被原 v3 正常拒绝；测试改为实际引用对应 material 证据，没有放宽生产证据校验。

第二轮 21 项中，跨商品现存 factId、其他 product/variant 身份复用两项出现预期 “Missing expected exception”。补齐存储关系校验后通过。其他两项失败分别是隔离环境备份路径验证、原生 1688 测试误比较其既有自动警告；前者用正常本地权限重跑，后者收窄为目标 SKU 属性原值比较，均未改变生产守卫。

## 新入库边界与固定规则

新增冻结 `source-attribute-normalization-v1.ts`，仅 `persistImport` 判断无重复回执后首次创建 facts 时使用。重复查询原本已位于 `BEGIN IMMEDIATE` 内，本轮保留该顺序、事务及原回执返回路径。不是在读取旧 product/receipt 时重新规范化。

- 名称只在有限宽度转换和外侧 trim 后精确命中固定名称集合时变化。集合包含现有明确的材质、颜色、形状、护理、布尔/分类属性与既有尺寸/重量名称；未知名称、型号字段、焦距等保持原名原值。不做模糊字段匹配、全局 case 折叠或 Schema 推定。
- U+FF01–U+FF5E 转 ASCII，U+3000 转空格；不做整段 NFKC，不折叠罗马数字、圈数字或连字。已识别普通文本属性仅做这类宽度与外侧空白格式处理，保留否定、内部普通空白和文字内容。
- 中文显示名保持原名，不把仅 haul 支持的中文别名永久改为跨 program 字段。模块不依赖当前 Amazon Schema、`sourceFactValue` 或后续可能变化的 alias 表；v1 回放规则固定。
- 测量属性仅完整匹配带明确、同类型单位的数值。24 种既有拼写统一到 mapper 与冻结 typed evidence 均支持的 `cm`、`mm`、`inches`、`g`、`kg`、`pounds`、`oz`，并保留原数字文字，如 `02.00`。不作物理单位换算、不四舍五入、不补单位。
- `m/meters`、错误类型单位、附加文字、裸数、型号、未知单位不纳入本轮转换。受支持测量格式仍由原 mapper 决定有效性，不把零或负值变成合法尺寸。
- source attribute HTTP 合同仍严格要求字符串：native `0`、`false` 原本被拒绝，本轮继续拒绝；字符串 `"0"`、`"false"` 保留，`ＦＡＬＳＥ` 在已识别属性中仅变成 ASCII `FALSE`，不引入新布尔推断。

每个原 attribute 创建一个独立 fact，顺序、source=`import`、sourceRef 和原有初始 state=`source_confirmed` 逻辑保留。多个原名归为同一个名称时不去重、不覆盖、不合并，也不自动选择一条。不同材质值仍使 mapper 不 seed；分类冲突继续由当前规则拒绝。之后人工设为 conflicting 的事实不会被重复导入改回 confirmed。

原生 1688 接收入口不变，SKU attributes 仍只在其来源回执中；妙手 selected dimension 和 SKU 规格也不进入本次公共 facts 转换。多 SKU 的全局测量依旧不能作为某个 SKU 的明确值。

## 回执追溯与历史校验

仅当实际发生转换，新回执顶层保存可选字段：

```text
factNormalizations:
  version: source-attribute-normalization/v1
  entries: [{ factId, attributeIndex, rawName, rawValue, name, value, ruleIds }]
```

rawName/rawValue 是已经完成 HTML 清洗和敏感内容处理的 snapshot 原属性，不能称为原始 HTTP，也不能据此恢复此前被清洗掉的外侧空白。ruleIds 为固定的 name-ascii-width、name-trim、value-ascii-width、value-trim、measurement-unit；只记录实际变化。

严格 validator 用冻结 v1 对 snapshot 重放，要求 trace 完整覆盖全部实际变化，索引、raw、结果、规则顺序均精确一致，UUID 唯一且不与本回执/product/variant 身份碰撞。拒绝未知版本、未知/重复规则、未知 key、缺项、错序、重复项和没有实际变化的项。旧回执没有该字段时不生成字段，返回旧结构。

主进程回执读取、同步 existingImport、重复导入与完整备份历史检查会验证尚存在的 fact 是否属于回执商品，并拒绝现存 product/variant/receipt 身份复用；完整历史检查也排除跨回执重复的声明身份。

这是创建时审计，不要求可变 current fact 的 name/value/source/state 仍等于当初创建值。用户后来修改、删除事实、重开、备份和恢复均合法。沿用既有 source SKU 删除后保留历史的语义：仅凭回执不能独立证明一个已经不存在的随机 factId 当年确实创建过，也不能提供防止所有协调篡改或整块移除 optional trace 的保证。本轮没有新增不可变账本或派生 ID 体系。

原 snapshot、mapping、skuMappings 不改写；receipt fingerprint 继续仅基于原来源内容。sourceImageMeasurements 的 hash 继续只取 snapshot/mapping/skuMappings，不包含顶层 trace。旧 source snapshot measurement projection 保持原读取语义：例如原全角长度仍可能不出现在该旧 projection 中，但新事实可独立进入 sourceAttributes 与当前 v3 文案证据；不能因此宣称所有 receipt-derived 测量入口都已修复。

4 MiB 回执限制仍在写商品之前检查，包含新增追溯开销。过大 trace 或随后写回执失败都会回滚商品、facts、SKU、工作区和 audit，不留下部分导入。

## 质量审查后的凭据守卫修复

独立 QUALITY 发现新转换绕过原检查边界：`service.request` 在清洗、HTML 解码后的 snapshot 上检查凭据，但首次建立 facts 时才进行的全角 ASCII 转换可能重新生成 appKey/appSecret；转换后的名称、值与 `factNormalizations` 都可能持久化敏感内容。合成凭据探针通过公开 preview→import 复现了该问题，未使用真实凭据或真实网络。

公开导入和同步导入现在都经过服务内部 `persistProduct`；它核对当前 scope，再向持久化函数传入同步可信守卫。守卫在事务的 duplicate 提前返回之后、转换和 4 MiB 校验完成之后、任何业务 INSERT 之前，对完整 facts 与 receipt 使用既有 `redactCredentials` 机制检测。只要结果会被清洗就以 `RESPONSE` 拒绝，并回滚；不将凭据复制到业务字段、不静默重写 snapshot/trace、不改变 frozen v1 回放规则。低层持久化保留可选检查钩子供可信调用者使用；当前所有生产导入入口统一经过服务守卫。

重复导入仍返回原回执，不重新转换旧 facts，也不对旧业务记录进行新的凭据检查或迁移。缓存预览、重开后 unchanged 暂存导入、暂停任务 resume 的已缓存和新抓取项均经过同一守卫。旧 snapshot 中全角形式本身的检测能力保持原范围，本修复阻止新增转换生成 ASCII 凭据，并不宣称扩展了通用字符编码秘密检测。
