## 实现任务：统一最终售价核对与局部重算

### 文件职责与预期变化

| 文件范围 | 修改目的 |
|---|---|
| `src/shared/listing-rules.ts` | 复用同一费用/ROI 计算计算任意实际售价；必要的新依赖快照类型，默认规则数值不变 |
| `src/main/pricing/`（小型定价文件，按需创建） | 最终 offer 解释/利润核对、定价依赖有效性及可复用的历史定价验证；不依赖高层任务编排 |
| `src/main/amazon/business-rules.ts` | 明确应用规则时，仅刷新仍能证明为程序生成且未编辑的报价；保留人工价格并核对实际值 |
| `src/main/amazon/pricing-inputs.ts`、`pricing-guard.ts` | 共用定价输入与新付费前资格检查，避免自行推导不同结论 |
| `src/main/amazon/service.ts` | 只读重评保留人工 offer；本地/平台预览、正式提交及最终发送检查接入同一判断；保留旧写入锁和历史 |
| `src/main/automatic-listing/outcomes.ts`、必要的记录校验调用方 | 队列与重新纳入不接受不合格实际价格，区分过期资料、报价淘汰及格式/系统问题；不反向要求定价模块依赖任务内部 |
| `src/main/listing-ai/history.ts` 及必要的定价消息调用方 | 向后兼容旧记录，并理解新增定价证据；不放宽其他业务历史验证 |
| 本计划、架构讨论文档、午间进度记录 | 记录授权变更、五题确认、实现内容与未验证范围 |

### 必须保留的行为

- 符合既定规则的人工改价可以使用，不要求等于程序建议价格。
- 即便自动促销生成关闭，实际 offer 中已存在的促销仍需核对。
- 包装参数、采购成本、销售数量、有效费用/价格变化可影响定价；无关文案、图片或设置修改不应使已证实利润淘汰重新进入队列。
- 用户尚未采用的新来源不改变冻结任务；本轮不增加自动付费、重生图片、重置预算或自动平台修正。
- 平台 UNKNOWN、提交意图和锁优先保留；价格检查不能将已发送未知写入当作未发送。
- 新规则不得重写已经保存的历史请求/响应、提交身份或付费结果。
