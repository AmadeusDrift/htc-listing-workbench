# 继续任务轻量化与原任务从头核对

基线bcd3048，独立分支fix/htc-light-tasks。已读本树AGENTS、固定认知、继续卡顿深入审查及17时实际阻塞记录；只实施任务协调叶子，不改来源/字段恢复算法、图片规则、UI或共享API，不操作真实AppData、330任务、付费服务和平台。

## 已实现

- 普通确认继续只检查任务可启动状态和固定店铺/规则/托管范围，不在确认前后反复遍历全部来源。界面先收到进度并让出响应机会；每个SKU真正轮到时才核对来源、原请求、策略和销售选择。原公开同步prepareStart兼容入口仍保留完整范围检查。
- 不再给全部选中行同时更新lastContinuedAt。内存调度授权只保存本次用户确认时间和已准备的SKU集合（重启失效，不是新通用缓存）；处理当前SKU或明确的来源兄弟项时才保存该行时间。它使用同一确认时间，不能在本轮新失败后自动铸造新的重试授权。
- 旧FAILED文字本身不让调度器跳过SKU；当前SKU先按原请求/提交状态判断。原提交转原READBACK，UNKNOWN由既有owner核对/恢复，仍未确认则只停该SKU。原来源、草稿、成功字段和图片、累计次数及费用不清空；稳定业务筛除保持。
- 定向预览说明来自已保存任务行，明确“到该SKU时核对”，不假称已核七图/Schema当前可复用。确认后不再重跑两轮全历史预览；实际使用仍走当前SKU原检查和owner校验。
- save支持内部显式changedKeys，常规单SKU步骤只传本行；来源/分类/销售family的实际关联行明确传keys。未知特殊调用保留旧安全fallback。跨行SKU唯一性、来源/卖家/范围、原请求/次数、原子检查点及CAS继续有效。
- resumeScope设置/移除通过原任务JSON局部patch，不再仅因选择范围变更强制解析整批payload。持久任务仍为完整JSON兼容快照，没有物理拆表、Schema迁移或备份变更。
- 外部AI/托管提交改变data_version时，持久任务若与原已验证基线完全相等，省去第二次完整业务parser；正文有任何差异仍走原严格校验/版本判断，同revision篡改仍拒绝。没有跨等待复用新的业务权限。
- ExecutionService新增main只读hasPendingSubmission(draftId)，复用原判断语义、不克隆全部执行任务；旧测试/依赖没有此方法时仍原list fallback。

## 从头开始与费用边界接口

main新增：

```ts
confirmStartOver(id: string, confirm: (task: AutomaticListingTask) => Promise<boolean>): Promise<AutomaticListingTask | null>
getCurrentRound(id: string): { roundId: string; startedAt: string; mode: 'continue' | 'from-start'; taskRevision: number } | null
```

仅可启动状态使用。显式从头开始复用原task id/SKU，以现有recheck范围标记未完成SKU；处理时先原请求恢复及正常来源入口，跳过前置整套预检，避免旧未知文字挡住本地恢复。已成功成果按owner现有状态复用，不新建替代任务/身份，不重画成功图，不恢复已用次数。已完成/业务筛除项保持；已提交未完成项只原回读。

首次普通启动或显式从头开始在排队事务中追加automatic-listing.round-started审计事件，detail为version=1、taskId、roundId、startedAt、mode、taskRevision；不改任务结构。普通继续/暂停恢复沿用roundId，不能每点继续都归零。getCurrentRound每任务最多精确读取最新一条后保留已加载元数据；新轮事件提交后更新该元数据。新轮只供“本轮新增费用”展示边界，历史真实费用/未知预留及M07预算账完全保留。根进程负责IPC/UI及明确原调用归属的费用投影。
