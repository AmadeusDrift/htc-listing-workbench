# 字段证据契约与历史读取隔离

日期：2026-10-10。分支：`fix/evidence-contract`，从已验证集成提交 `01486ed` 开始。本文记录实现、独立规格/质量复审和父任务最终验证；真实店铺与发布包验收不包含在本次结果中。

## 根因与修复

字段别名、分类值解析和一般语义判断曾使用不同入口。`适用人群=成人` 与 `适用年龄=成人` 对 audience 的结果不一致；有直接来源但无法解析时，分类校验把空的期望集合当作放行条件；context 又会删除 conflicting 事实，导致后续看不到阻断依据。

共享的 v1 判定返回 supported（规则和证据 ID）、conflict（来源冲突或值不符）、unparsed（来源缺失、来源无法解析或候选无法解析）。只有来源确实缺失才保留既有普通属性 infer 白名单、真实相关引用和非空理由。存在但无法解析的来源不能由审核 PASS 或 infer 绕过。

复用既有字段映射和 selected SKU 属性解析，增加有限桥接：明确年龄支持对应 audience；明确肯定的手动动力支持 Manual operation。canonical `target_audience`、`target audience` 与已有中文 audience 别名进入同一年龄角色，不能忽略直接相反的人群事实。通用/General/All 不推出 Adult；新桥接拒绝“不适合成人”“非手动”“非电动”。成分只使用有限翻译词典、明确英文原值及无序同集合比较，支持柠檬酸/Citric Acid、水与香精，不推任意化学翻译或新增浓度。合法非织物 fabric Not Applicable 的既有许可保留。

context 只在实际存在阻断时加入 `evidenceBlockers`：唯一角色、唯一事实 ID、有界事实列表及固定 source_conflict 原因；这些 ID 不能成为正向引用。处理顺序保留销售配方投影、所选 SKU 优先级与多 SKU 颜色/尺寸/件数范围排除。选中 SKU 的明确属性覆盖共通冲突；兄弟 SKU 不能清除当前 unknown。若所选 raw age 覆盖冲突而 age 卡未激活，仍保留有效所选证据并移除共通相反事实。无 blocker 的旧 context 表示、顺序和 hash 不回填变化。阻断只影响相关字段或实际涉及该角色的文案，普通无关材质文案仍可通过。

## 当前授权与历史规则

当前 `validateAiResult`、候选生成/复核/采用及当前复用默认严格，无 marker 也不能选择旧规则。模型不能写版本标记。主进程为新 listing/image AI 结果以及新图工作流写可选 `listingEvidenceContractVersion='listing-evidence/v1'`；旧 context、category policy、采用记录和图片 hash 不做统一迁移。

纯读取使用显式 stored 入口：AI list/get/query、completion journal 保存结果、两处备份读入、listing/image history、image versions 和 workflowRuns。未标记记录采用冻结 v0；明确 v1 采用冻结 v1。身份、上下文 hash、引用、成功调用、采用关联、图像和销售配方的既有检查继续保留。旧语义错误可以作为历史保存，不能凭旧 PASS 成为新授权。

图计划的 caption 会嵌套调用字段证据校验，因此 history 分发也传递到 `assertImagePlan`、`imageContext.setPlan`、workflow 的 setPlan、图文复核和 backup。旧 caption 使用当时完整的 v0 图像文案规则，不额外套 listing 的历史 category 豁免。新图结果与新 setPlan 外层版本保护 v1；旧结果仍保持原 JSON bytes 和 hash。当前执行不传 stored 选项，并在恢复、复用与生成入口再次检查当前 copy 和 setPlan。

版本依赖固定在 `evidence-validation-v0/v1`、`evidence-category-v0/v1`、`evidence-contract-v1`、`evidence-semantic-v0` 与 `evidence-colors-v0`。`stored-evidence.ts` 显式匹配固定 literal v1。后续否定解析、字段归一等语义变动须新增 v2 与显式 stored case；不得修改 v0/v1 所依赖的 parser、alias 或语义 helper，也不能仅 bump “当前版本”常量。图历史的语义分发应沿关联结果/工作流保存的版本继续传递，保留无标记和 v1 fixtures。结构或图计划规则将来若发生语义改变，也须保留其历史边界。

## 继续入口的范围

- 幂等 adopt 在新增 schema fresh await 后以及返回前继续检查 signal 和审核设置；取消不写采用历史。
- complete 恢复保存候选时先走当前严格校验；DONE 历史原样保留，但返回当前 evidence remaining，零自动新调用。
- review-disabled snapshot 拒绝已有直接来源的 conflict/unparsed/value mismatch、blocker 和所选 SKU 矛盾。来源缺失的既存人工/普通判断继续保留，不伪造 infer 理由。已知 AI adoption 的当前复用仍检查其原始 infer 义务。
- 图流程 COMPLETE 快返、缓存 copy、approval reuse、recheck、已有 imageContext 的恢复、legacy run 与 AiService 的真正图片请求入口检查当前契约。complete 的政策拒绝在 catch-all 新建流程之前发生，不能改走新付费流程。
- `approvedWorkflowAssets` 的简化 context 不含 source_image 观察，故仅对当前直接冲突执行确定性检查，并对本契约角色的有效 adoption 在原完整存储 context 中检查候选许可。它不删除额外图像引用、不声称图像 freshness。完整当前 context/citation、旧 PASS 和像素新鲜度检查继续在有正确输入的 ListingAi/ImageWorkflow/AiService 授权路径执行。真实测试覆盖 age 的 source_absent infer 同时引用材质与 source_image，以及 color 采用后七图复用。
