## 修改

规则服务随工作区生命周期复用连接，每次仍从 SQLite 读取最新规则；适配事务直接使用事务连接读规则，不缓存规则值。

销售草稿通过 SKU、配方 key、product_id 的索引候选并集读取，再沿用原先完整的店铺、来源、配方、父子体及提交状态判断和排序。UNKNOWN/已提交优先、重采集身份、旧单件草稿兼容不变。选择 SQL 索引而非 create 局部历史缓存，是因为适配与创建末尾保护都需要实时观察跨连接的旧提交状态，不能用过期快照绕过 UNKNOWN。

create 每来源让出一次事件循环。末尾重新核对全部实际采用来源（含重采集沿用的旧来源）、来源回执、规则、店铺、图床、相关任务 revision、旧销售草稿、用途 preflight 与 Batch 计划；任务、来源冻结和批次关系仍在原有单事务内保存。无关任务的进度变化不使当前创建失效。assertScope 仅在一次同步检查内部复用来源及指纹，不跨异步阶段缓存。
