## 根因与结果

原 FTP 控制和数据均由 basic-ftp 使用 Node TCP，没有独立线路选项；Electron 的 DIRECT 无法表示绕过 Windows TUN。新增设置页“直连（跟随系统路由）/代理转发（本地 SOCKS5）”及本机端口，明确直连无法保证绕过 VPN/虚拟 DNS。代理限定 127.0.0.1 免认证 SOCKS5，目标 DNS 委托代理，控制及 EPSV 数据连接使用同一原 FTP 主机名；不静默走直连，不更改系统代理/VPN，不新增依赖。远程 DNS 无法获知可信远端 IP，因此代理路径不接受 PASV 改投，服务器不支持 EPSV 明确返回 PROXY_PASSIVE_UNSUPPORTED。FTPS 控制/数据保原主机身份、证书校验和会话绑定，不降级明文。

托管原失败记录有 CONNECT_TIMEOUT，但 execution 只显示“图片尚未完成托管验证”。现在保存安全码、连接/目录/查大小/上传/外链阶段及本次尚未发送、结果未知或远端大小已确认；执行提示增加第几张和累计次数。原始服务端文本/凭据/路径不进入错误文本。旧记录缺阶段明确显示“历史记录未细分”，不伪造细因。
