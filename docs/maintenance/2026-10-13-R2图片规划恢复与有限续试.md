## 行为

- 新本地恢复结果使用 `image-plan-recovery/v2`。旧 v1 继续走原对象解析路径，原始响应/原调用/费用账本不改写。

- 确定性修复仅将 JSON 字符串内部未转义控制字符转为 Unicode escape；转义中的控制符、引号、括号、对象/数组结构、尾随内容和未闭合字符串不猜修。之后执行完整既有图片计划、证据、尺寸、SKU、冻结 slot 校验。
- 普通 uncertainty 单项上限从 200 增至 1000 字符，数量仍最多 10，不截断、不删除。测量和引用保护未放宽。
- 自动任务同一 workflow/context/slot 的规划累计最多 3 笔。读取已有 ai_calls，包括匹配上下文但没有 request hash 的旧记录；改变 repair feedback 不重置次数。发送前检查，并在原 usage.reserve 写事务中再次检查（含本次 reservation），防止不同 service 实例竞争越限。
- 在同一个已启动 imagePlan 调用内，只有有 callId 的 OUTPUT_INVALID 可有限续试，先尝试恢复原响应。无新 callId、取消/暂停、来源/配置变化、额度不足、明确 refusal/tool-call/credential echo 不自动连续付费。已知拒绝诊断在后续继续时也阻断。
- 精确 request hash 的已成功 workflow 规划可复用。受限修复仍要求精确原 repair 身份；无依据的旧 hashless repair 不复用。原 workflow、图片尝试和已通过图片不重建。
- 后续请求带固定、安全的 validationFeedback：完整 JSON、仅用当前证据 ID、选中 SKU、不从全商品颜色规格或无单位尺寸推测、保留冻结文案。没有回传未信任原文作为指令，feedback 不影响预算身份。
