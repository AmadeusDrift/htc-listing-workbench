# P01 外观审核数量与细微差异

按本批批准计划，在独立 review 工作树处理。原提示要求每张图覆盖 supported sale quantity，并把视觉不足一概判 UNCERTAIN；单只使用场景因此被要求证明50只整包数量。提示也未明确非功能小凸起与关键结构的轻重边界。没有改原回执、既有候选或真实任务。

仅修改 `appearance-adapter.ts` 发给现有外观审核用途的提示：

- 代表性单只使用/场景/细节图可展示多件装中的一件，不因缺少整包视觉证明而判不确定或错款。只检查明确数量主张、明确整包销售内容表达与原事实的冲突，例如明确10只装与所选50只装矛盾。参考照片张数不作件数。
- 不改变主体、功能和销售内容的细微装饰、边缘、非功能凸起只在原检查 reason 中提示，其余相符可 PASS。错款、错所选颜色、关键部件缺失/新增、功能结构改变继续 MISMATCH，遮挡或无法判断重要特征继续具体 UNCERTAIN。
- 保持严格结构、引用及候选/规划身份；不从 reason 文本启发式改写模型 verdict，不将旧拒绝直接改 PASS。原困难审核至多一次及 UNKNOWN 不重发继续沿用。

测试先增加两项实际发出提示契约回归，未修源码均预期失败；修改提示后，`node --test tests/image-appearance-policy.test.ts tests/image-appearance-review.test.ts` 14/14通过（约0.76秒）。覆盖发送源图/最后候选、原Luna/medium、提示中轻重边界、合成数量/细微差异PASS及四种明确MISMATCH/遮挡UNCERTAIN结果不改写，原状态机不重复审核/不增加生图尝试。另 `node --test tests/image-review-tolerance.test.ts tests/image-set-rules.test.ts` 29/29通过（约0.82秒）；`npm run typecheck` 与 `npm run check:boundaries` 严格检查通过。

这些是提示契约、适配器与状态机验证，合成模型返回不能证明真实模型必定正确辨别视觉细节；未发真实模型请求，未人工复核本轮旧凸起候选，未为旧候选重新付费或解锁。整套同源集成/构建与候选EXE由主进程统一完成，无DDL/配置迁移。
