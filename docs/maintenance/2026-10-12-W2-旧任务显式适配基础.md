# 2026-10-12 W2 旧任务显式适配基础与验证边界

本提交提供可离线验证的旧任务检查与显式应用入口，不表示 W2/W12 全部历史形态已经验收。未操作真实任务、AI、Amazon 提交、审核开关或真实数据库；未发布。

## 已实现

- 自动任务页面只读检查旧任务，展示来源、规则、销售选样、字段、本地校验和需保留的历史。来源展示使用 `WorkspaceStore.getProductSnapshot`，不调用会修复关联的 `getProduct`。
- 预览不分配 SKU、不发远程请求、不保存任务/草稿。检查令牌包含任务、来源快照、规则、收据、草稿、工作流、执行任务、AI/字段操作状态及命名状态。应用前再次核对磁盘记录及当前依赖。
- 用户点击“适配当前规则”后仅保存本地更改，任务成为 PAUSED；用户另行继续。正在进行的任务/请求只等待完成，不取消。
- 同一个 SQLite 事务包含销售命名分配、草稿本地更新、任务保存和适配审计。保存失败整体回滚；重复相同令牌不重复分配或记录。重启保留检查点与旧任务身份。
- 按完整来源重新选样，补入旧任务中不存在的新选中销售项。保留旧行历史；未选中与利润淘汰分开。既有独立草稿冲突时整体停止应用，不创建重复身份。
- 已提交/回读/标签/完成行保持原内容。规则历史由任务检查点及审计证明，旧结果不需要改写为新规则检测。
- 本地草稿适配只刷新未被手工修改的规则字段，保留 AI/手工属性、原始响应和平台错误；重新本地校验。较旧缓存 Schema 不覆盖草稿；仅 enumNames 展示差异不更新语义。
- 利润淘汰重新计算当前报价，仍不合格继续 SCREENED；只有完整当前合格报价才恢复为待执行。原错误及结果保存在适配前审计，图片/字段次数、操作/执行历史不重置。
- 七张已通过图片在成本/库存等不影响外观的来源变化后，可保存独立的精确依赖复用证明。原图片工作流、请求上下文、审核结果、次数完全不改写；当前来源/属性再次变化会使证明失效。

## 仍需集成完成的范围

- 部分已付费图片工作流发生来源版本变化时，其原请求/图位上下文携带旧 productRevision。当前实现明确将该行列为 BLOCKED 并保留原成果/次数；其他行可继续。尚未实现这类逐图新上下文接续，不能称为 W2 完整交付。
- 真实商品事实、销售组合或实质 Schema 变更影响旧图时，仍需针对受影响图位重新核验，当前不会清空整套再生成。不可把此保留策略描述为已完成自动局部重做。
- 图片风险淘汰原检测结论保持原样，需与 W11 的当前阈值解释衔接；这里不虚构新检测通过。
- 历史成功字段响应中被拒候选的本地重新采纳（62/63）、W3 未知操作恢复由独立工作包负责，本提交未修改原 AI 响应或伪造原调用状态。
- 本提交没有以真实 103 行任务做生产应用，也没有真实提交/生图验收。

## 验证

- 首个失败测试确认原服务缺少 previewAdaptation；实现后覆盖只读、不发请求、旧令牌拒绝、显式应用不继续、重复应用、保存失败回滚和重启。
- 同事务真实命名测试覆盖新增选样、保存失败时命名分组回滚、重试后原身份稳定。
- 真实本地 Amazon/定价夹具覆盖原始响应保留、手工属性保留、事务回滚，以及无关规则/成本仍失败/成本合格三种分流。
- Electron 界面使用隔离 userData、隐藏窗口和 HTTP 拦截，验证自动检查、保存失败展示、显式适配后等待用户继续。沙箱进程启动受限，已在宿主运行该隔离夹具。
- TypeScript 无错误；最终相关回归 223/223 通过，0 跳过（包含上述 Electron UI、自动任务、利润、命名和图片依据回归）。初次沙箱出现既有 SOURCE_CHANGED 文件视图差异，宿主模拟回归通过，没有放宽业务校验。
