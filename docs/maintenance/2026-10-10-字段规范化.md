## 入口与规则

只在新 generation/repair response ingestion 调用新 `normalization-v1.ts`。共用 `validateListingFieldsOutput` 不做规范化，历史候选、context、hash、审核和采用记录不迁移。

- 仅候选白名单中、当前 context 实际包含的字段值可转换；不改 field 名、evidenceIds、transformation、inferenceReason 或 missing reason，也不扩字段集合。
- 有限字符宽度转换：U+FF01–U+FF5E 转 ASCII，U+3000 转空格；再去外侧空白，不压缩内部空白，不做整段 NFKC，不折叠罗马数字、圈数字和兼容字符。
- 闭枚举先保留实际 exact literal；其他值只按 trim/有限宽度/case 唯一匹配实际 Schema 选项，并输出选项原文字面量。Blue/BLUE 等非唯一匹配拒绝；未知枚举不会得到任意默认值。固定单选也仍要求真实来源支持。
- 布尔仅现有三个字段：`is_heat_sensitive`、`is_expiration_dated_product`、`contains_liquid_contents`。原生布尔及有限 true/false 字面格式可变为原合同字符串。false 不被当空；字符串 `"0"` 保留原值，原生数字 0 继续按原类型合同拒绝，no/yes/0 不猜为布尔。
- 仅 `fabric_type` 的 N/A 或 NA 可映射到实际唯一的 Not Applicable/not_applicable 类选项，且须已有冻结非织物语义支持。Cotton、PLA 混 cotton、来源缺失、其他字段均不使用此映射；Schema 本来允许且有依据的精确 N/A 保留。没有全局 N/A 清空或填值。

转换后仍执行原严格 output、current v3 evidence 与真实 Schema 流程；未知 key、非法字段、缺 missing reason、来源冲突和兄弟 SKU 引用不被吞掉。generation 保持原候选/采用两层校验：候选通用限制及证据检查后保存，完整 Schema 不合格的值仍不能 adopt；repair 继续在保留单字段前检查当前 card 长度、数量与枚举。没有新建推断权限或补造缺失事实。

## 可追溯元数据与历史边界

实际发生转换时，主进程在 `AiResult` 外层保存可选 `listingNormalization`：

```text
version: listing-normalization/v1
entries: [{ field, index, rawValue, value, ruleIds, evidenceIds }]
```

rawValue 是模型返回的原候选叶值（字符串或原生布尔），不是商品事实、provider receipt 或 HTTP 原始字节。ruleIds 是主进程生成的 ascii-width、trim、boolean-literal、schema-enum、fabric-not-applicable；仅记录实际执行且值发生变化的规则。provider 自报同名根 key 或候选/item 额外 key 都不能授权或伪造 trace。partial 中转换过但最终拒绝的候选不留下孤立 entry。

严格结果校验绑定最终 field/index/value、真实 evidenceIds、非空且无重复的位置，以及可重放的精确 raw→value/rule 顺序；拒绝额外 key、未知版本、无实际转换、错误规则、错误引用及缺候选。trace 仅允许当前 v3 的 amazon-fields 结果，不允许旧 marker、review/image 结果携带。本元数据本身不授予事实或采用权限。

`listing-normalization/v1` 模块是冻结的记录语义。stored 读取只使用它验证已记载转换，返回已保存内容，不重新规范化 output/context。后续扩规则必须另立 normalization 版本并保留 v1，不能直接修改 v1 回放语义。非织物支持复用已冻结 `evidence-semantic-v0.ts`，三个布尔字段集合在本版本中固定。旧记录没有此属性时仍不生成属性，原 JSON/hash/adoptions 保留。

## QUALITY delta：原生布尔的 canonical 字符串精确选项

独立 QUALITY 指出原生 false 搭配真实闭枚举 `['false','FALSE']`（true 同理）回归。冻结 v3 parser 原本将原生布尔转成 canonical 字符串，并由 evidence validator 接受实际精确选项；本轮新模块只优先查原生 boolean 选项，未查已存在的 canonical 字符串选项，随后 fuzzy 匹配命中两个值而拒绝。repair 因而把合法布尔移入 missing。此前原生 `[false,'false']` 正控没有覆盖这一组合。

先新增 4 项正式测试：false/true × generation/repair，每项先断言冻结 `evidence-validation-v3.ts` 接受原输入，再经实际 mock transport 检查完整输出和精确 trace。目标命令 `node --test --test-name-pattern='canonical string enum preserves native' tests/listing-field-normalization.test.ts`：4 tests / 0 pass / 4 fail，267.8572 ms。两项 generation 报多枚举冲突，两项 repair 丢失布尔候选，均为真实业务断言失败。

生产修复仅 `normalization-v1.ts` 一处条件：原生 boolean 输入在实际 enum 包含 raw boolean **或** `String(rawValue)` 精确选项时保留 canonical 输出，记录原布尔和 `boolean-literal`。不把同样优先权给予 trim、宽度或 case 转换后的字符串，不改证据版本和旧 validator。该 normalization/v1 尚未提交或发布，本轮审查修正没有迁移历史版本。

目标 GREEN 4/4 PASS，252.6864 ms。再增加 2 项 false/true 非精确空白/全角字符串控制，generation 仍拒绝、repair 仅保留合法 material 且没有孤立 trace；新增 1 项主进程集成覆盖 false/true × generation/repair 的保存、严格 replay、篡改成模糊字符串拒绝、AiService 重启零请求读取。
