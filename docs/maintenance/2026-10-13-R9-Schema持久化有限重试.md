# 2026-10-13 R9：Schema GET 持久化有限重试

## 范围与行为

针对 76 的已确认链路：原实现已经有首次加两次正文短重试，HTTP 200 后正文仍可能未读完整。本次保留这三次短尝试，在原自动任务、原 SKU 行增加有限延迟 Schema GET，不重建任务、不清空图片/字段/预算、不重试利润淘汰项。

- 只将 Schema 定义 GET 或 Schema 正文 GET 的网络/超时/正文读取中断标为 `SchemaTransientError`。保存经过验证的 target/productType/requirements/parentage/locale，不保存预签名 URL。checksum、大小、JSON、地址/重定向和授权错误不进入延迟续试。
- 可选严格 `schemaRetry` 记录保存范围指纹、原阶段、首次失败、到期/截止时间、已用轮次、状态与固定原因。旧记录没有该字段仍可读取。默认最多三轮，间隔 30/90/180 秒，首次失败后十分钟截止；发 GET 前先持久化本轮使用与下一到期时间。
- 复用五秒观察调度和当前会话授权。到期时直接 `amazon.getSchema(selection)`，等待/失败期间不调用 `prepareItem`；GET 成功且生命周期/版本/范围仍一致后，才接续原未完成行。
- 暂停、取消、确认窗口、调度挂起、失去授权均不新发 GET。关闭等候正在观察的 GET 返回。重启将等待记录暂停，保留轮次且没有授权；用户显式继续不重置次数。Schema 成功后后续步骤失败仍可走原来的显式继续。
- 恢复旧备份合并同任务同行已有的 Schema 预算，不回退轮次/截止时间，不授予执行权限。缺失的新任务不会在旧备份凭空重建。
