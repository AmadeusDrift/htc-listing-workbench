# R02：已收到字段响应的本地恢复

日期：2026-10-11。修复分支：`fix/known-field-response-recovery`。基于已合并的 R01 字段解析兼容调整。

## 行为与边界

用户继续字段任务时，在原冻结上下文下读取对应失败调用的完整诊断响应，使用 R01 解析器恢复字段。`ai_results.localRecovery` 保存原文、原文摘要、上下文摘要、原操作 ID、解析版本和恢复时间；恢复结果与操作引用在同一个事务内提交。原 `FAILED / OUTPUT_INVALID` 调用、完成时间及费用流水均保持不变。

读取进度、列出结果和启动服务不会触发恢复。只有明确的响应接收标记、输出拒绝元数据或身份完全匹配的诊断记录能证明已收到响应。一般 FAILED、超时或无响应仍按结果未知处理，禁止自动重发。原文缺失、截断、身份不符或仍无法解析时，保留原记录并给出“已收到响应，无法本地恢复”的原因，不进入新的付费请求。

本次恢复范围仅为完整 Schema 的字段生成响应。字段复核响应可辨别是否已收到，但尚不自动重解析；无法恢复时明确提示。已恢复结果的读取、采纳、历史验证及备份采用同一调用归属规则，原失败调用不能拥有普通的成功结果。恢复原文随现有 `ai_results` 备份，不依赖外部诊断保留期。

显式继续时，先按原冻结上下文保存已知响应，再沿用当前产品、SKU、草稿及 Schema 的完整新鲜度检查。实际输入变化时，恢复结果仍保留，但不会写入过期草稿。剩余项 R21：方案中“仅重判受影响字段”的跨真实输入版本自动采纳尚未实现，不能把此项记为完成；该限制不影响本批上下文未变化的 19 份响应本地恢复。解析版本 `full-schema-recovery/v1` 表示本次 R01 解析语义，后续改变其语义时必须保留该版本历史读取兼容，不能把历史恢复结果改写为新解析结果。
