## 修复

1. **GET ERROR 不证明本轮 PATCH 被拒绝。** 原实现会将范围内 ERROR 直接转 REJECTED 并释放写锁；旧错误/旧属性原样回读也能触发第二轮。现记录为 ACCEPTED 等待，明确“问题可能来自原提交，未证实本轮失败”，保留锁、请求和观测；反复继续只核对，不重发。即便目标值已匹配而 GET 仍有范围内错误，也不将其推定为本轮终态拒绝。
2. **自动第二轮仅由可靠同步 INVALID 开启。** 必须是本 SKU、可读且含 ERROR 的同步 INVALID 回执，仍遵守已确认范围、载荷变化和两轮上限。未实现其他异步终态证明通道；GET 问题变化本身不会放行第二次写入。
3. **后续修正使用已核实完整基线。** `originalAfter` 基于 trustedFacts，而不是重新取未修正的原 submitted。trustedFacts 仅吸收同 draftStamp/listingHash、SKU 匹配的 ACCEPTED + VERIFIED 历史，且历史回读与当前远端字段都精确匹配当时 after。color 已 VERIFIED 后的 material 修正不会被原 color 非法枚举误阻断。
4. **已删除字段实际 delete。** 兼容无 v2 scope 的旧自引用删除历史；不向基线写入 undefined。字段比较先检查属性是否存在，缺失只与缺失等价，防止删除/远端漏字段触发 `correctionHash(undefined)` 崩溃。远端漏目标字段保留 ACCEPTED 锁。原提交没有包装自引用而远端新增时，明确报告原可信提交不一致，零发送，不能自动删除。

原 SKU、原 submitted request、已通过图片、发送/回读历史均未覆写。无迁移或新增 SQL 权限。
