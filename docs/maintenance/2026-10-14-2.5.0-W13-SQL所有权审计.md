## Gate 能证明什么

- npm run check:boundaries 及 module-dependencies.test.ts 的 strict 调用执行 AST 值依赖检查与 SQL gate。
- 检测 INSERT / REPLACE / UPDATE / DELETE / CREATE TABLE / ALTER TABLE / DROP TABLE 的静态字符串与模板；识别引号表名与 schema 前缀。UPSERT DO UPDATE SET 不计成表 SET；值字符串、注释及普通 UI 字串不计写表。
- file + enclosing command + operation + table 必须精确登记；SQL 形状变更或同语句新增出现次数也阻止通过。新增跨域写入不能仅因目标表已有 owner 或源文件已登记而放行。
- prepare/exec 的非字面表达式必须逐条人工登记；现有 38 个候选含 RegExp.exec / 非 SQL prepare，清单说明实际接收方。真实 SQL 表达式仅受控事务控制、固定迁移 schema/index、两个 completion SELECT 拼接。
- 动态建表模板单独登记，并校验 SOURCE_TABLES 与 CONSISTENCY_TABLES 的精确成员及其 owner。新增成员不能沿旧模板绕过审计。

这是有明确边界的静态新增违规 gate，不是 SQL 解释器或全程序权限证明：无法用 regex 穷尽经别名、多层拼接、外部代码加载而来的 SQL，也无法仅由字符串得知绑定参数的业务语义。现有动态表/表达式已人工核对；shared key 以 runtime assertOwner 补足。后续修改 adapter 参数、动态 SQL 来源或恢复路径仍须人工审阅。不得把零扫描错误宣称全部潜在穿透已形式化证明。

## 恢复、维护与迁移权限

- backup.disconnectSnapshot 只负责已认证备份的 staging 数据库，retainSafetyHistory 将原数据库的保护历史并入候选；继续保留 UNKNOWN/费用/预算/锁，不授权真实任务重发。
- database.openDatabase / storage.migrations 仅既有显式版本迁移；schema/index 常量和版本顺序保持原保护。没有新增删历史、清理 UNKNOWN 或日常查询触发迁移的行为。
- AmazonPersistence 的 putTarget、putSchema、persist、写锁/调用记录及 cleanup 是历史多职责方法，已按实际表和方法职责逐项登记；cleanup 仍由既有引用/保留期保护，审计没有扩大删除范围。
- WorkspaceStore 的资产、商品与采集收件方法同样按实际职责登记，保持现有事务/revision/归属验证；不会把 store 名字当全表所有权。
