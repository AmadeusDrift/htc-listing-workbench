# P05：历史失败、定向接续与从头检查

日期：2026-10-14。独立分支 `feat/htc-250-targeted-resume`；复用 P01/P02 基线，并整合 P03 `33d3ac4`。未修改正式程序、真实库或真实请求。

## 实现

- 自动任务 JSON 保存失败事件 v1、最近继续时间、所选 SKU/图位范围。旧错误在继续前归档；已知图位 `failureProof.at` 保留原时间与位置，没有原时间则明确未知。当前检查事件与原请求凭据分开，不使用 classifiedAt、刷新时间或 run.updatedAt 冒充原失败时间。原因显示前隐藏凭据、任意协议 URL 和结构化请求内容。
- 新接口 `previewAutomaticResume` / `resumeAutomaticSelection` 经过受控 preload 和 IPC；逐 SKU 异步让出事件循环，返回本地证据 token 与真实处理/复用说明。确认前后复验任务版本和来源、草稿、图片、执行、托管快照；原生确认仅批准所选范围。普通继续会重新展示全任务授权，不沿用此前局部确认文案。
- 调度、来源准备、Batch authorize、等待结果采用、Schema 等待恢复、后续备货只执行授权范围。同来源/同父体的必要依赖仍检查；其他未选商品变化不能阻断健康所选 SKU。Batch flush 使用现有逐项 authorize 门槛；原混合 prepared 批次不能因局部选择绕过整体授权。
- 图片图位选择传入原 image workflow owner，规划/原响应恢复、下载、候选复核与生成只遍历所选图位；已通过图位复用。P03 历史补额也限制到所选位，未提供整套规划时不能伪装为具体图位授权。局部图片操作在图位处理后停止，不上传、不发布；其他旧失败不成为本次新失败。
- 从头检查有独立执行分支：重新核对来源一致性、当前本地字段/事实/规则、提交锁、七图审核与关联、本地图片文件内容、托管记录。即使已到 EXECUTION，也先检查早期失效。可修字段转入原有有界 FIELDS_PENDING 修复；缺事实、缺证据、规则/Schema 待适配、文件/审核失效等明确停止并说明。有效文案、图片和托管成果不清空，远端 URL 有效性仍由原执行 owner 在实际执行时核验，预览不会发远端请求。
- UI 提供具体 SKU、多图位、处理/复用预览及确认按钮。选择列表复用 20/50/100 分页、跨页保留选中。已接收 SKU 的入口说明保留原图并转原 SKU 处理；不调用 correction send，也不绕过 P06 的原生范围确认。

## 边界

以上是服务、契约与真实组件的离线证据，不是正式库、完整安装包或真实在线成功率验收。P07 负责整合 P04/P06 后的完整 APP/候选验证。原 SKU 修正仍由 P06 的独立确认和发送/核对规则负责；规则/Schema 发生变化仍使用已有“适配当前规则”入口，不能把资料不足或 UNKNOWN 当作通过。保留原次数、预算、成果和 SKU 身份，不提供全部重新生成或重置次数功能。

## P1 补修：图位授权不能扩大为整套复核

独立审查发现 complete 内的四个整套 recheck 出口原来未传递 selectedSlots。现四个出口统一通过 `recheckWholeSet`：图位局部请求同步拒绝，提示“当前需要整套审核策略重新核验，请按SKU预览并确认范围”；全 SKU 明确授权仍使用原整套复核流程。未通过过滤循环冒充全局审核策略已经通过。

新增真实图片 fixture：关闭 copyReview 完成七图，开启 copyReview 后选择图位 2；补修前可复现 Missing expected exception。补修后拒绝且调用数组、完整原 workflow/七图保持不变；正常全 SKU 接续复核成功，generation 新增为 0。相关三个图片测试全部通过，typecheck 通过。仅合成假服务；与前述测试相同，因 Windows 文件 realpath 限制在隔离目录运行 require_escalated。

## 集成补修：可信分类优先于任意服务文本

冻结版 totals 回归复现 FAILED + FIELD_RESULT_UNKNOWN 被 raw error 优先返回，绕过“结果未知/禁止重发”等可信提示。现规则淘汰优先使用结构化 code，随后为已知安全/步骤原因及 UNKNOWN，最后才展示普通失败的脱敏细因；即使历史规则行错误保存为 FAILED，也不能由 raw error 覆盖规则原因。保留原测试安全断言，新增 SCREENED/FAILED 规则行与普通图位下载细因对照；14 项 reason/history/group 回归通过，typecheck 通过。未修改主进程冻结工作树。
