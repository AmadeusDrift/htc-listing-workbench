# 候选制品追溯与隔离验收

分支：`chore/release-verification`。实现与源码验证已完成；实际候选构建和运行结果在源码 S 提交后补录。当前没有启用新包，没有修改 `release/HTC-1.0.0-win32-x64` 或正式启动器。

## 原因与修复

原 `package.mjs` 对固定目录执行覆盖，已有 HTC.exe 时复用旧 runtime，按本机文件存在性复制历史业务文档，并在打包时重写 tracked notices。旧摘要仅包含部分文件，校验依赖当前 cwd 的 dist，未绑定已提交源码。

- `snapshot-release.mjs --source-repo <repo> --output <new-run>` 要求真实源仓库干净，输出必须是其 artifacts 或 .test-data 内的新目录。用完整 HEAD 的 tracked-only `git archive` 创建独立源码；Git for Windows 会按 eol 属性转换 archive 字节，因此随后从同一 Git blob 批量读取原字节，规范化为精确提交内容。记录 commit/tree、完整 mode/blob 清单、每个源文件大小/SHA-256、lock 与源清单摘要。验证时重新读取显式仓库的 Git 对象，不依赖快照上级目录的 HEAD，也不接受手填 commit 标签。
- 本机 node_modules 使用普通独立副本，核对复制前后完整摘要和锁定版本，不执行 install。快照内运行既有 `npm run build`，构建前后重验源文件及依赖。回执保存真实命令、Node/npm、编译器 hash、Electron 版本与完整 runtime、构建输出摘要。Git safe.directory 仅在该次只读命令中指定，不改仓库或全局配置。
- package 只接受显式新候选目录，拒绝已有空目录、已有 EXE、protected/父路径重叠、UNC、穿越和链接。独占创建后复制全新 runtime；失败目录保留为未完成，不支持 force 或复用。直接生成候选 notices 和简洁说明，用户文档白名单为空；只分发 tracked 合成 samples，不复制历史 docs、source maps、native 生成源码、测试 guard、测试库或业务配置。
- 完整递归 manifest 保存自身以外每个文件的相对路径、大小和 SHA-256，包括 runtime、locales、资源、应用、模板与许可。独立校验缺失/额外/大小写重复/无效路径/链接及 Windows reparse point/内容变化。即使更新 manifest 摘要，也必须匹配源快照、构建回执和 runtime 的输入摘要；额外加入并自列清单的历史文件仍拒绝。包外 receipt 保存 manifest 和文件清单摘要。它是本地追溯/完整性证据，不是数字签名或对恶意修改整套证据的密码学认证。

## 隔离运行

`e2e-release-candidate.mjs` 先完整校验候选，显式启动其 `HTC.exe`，创建全新专用 workspace。通过该新进程的回环 `--inspect-brk` 在主入口执行前核验 EXE/dataRoot/未 ready，并注入包外测试 guard；注入失败不主动恢复未保护的主入口。不增加生产环境变量绕过、付费解锁或 IPC 能力。

guard 拦截 Node fetch、HTTP(S)、TCP/TLS、HTTP2、DNS、UDP、WebSocket，以及 Electron net/session fetch/request 和 Chromium session 请求；允许应用本地 red/red-asset/file/data 资源。运行记录只记 transport 类型，不记录凭据/请求体。`RED_E2E=1` 仅用于隐藏窗口，禁网由 guard 独立承担。新增 session 同步安装拦截。

候选 runner 核对 process.execPath、app.getAppPath、版本、Electron identity、185 项精确 API 和 renderer sandbox；实际运行 safeStorage 加密/解密、SQLite 写入/重开、nativeImage PNG、真实 preload/IPC 本地合成商品与图片协议预览、同 EXE 重启后的商品 ID 与密文保留。截图、报告和合成商品记录写包外测试目录，结束再验证包摘要。guard 的故意出网反例单独计数，其余阶段要求零出网尝试。此脚本不会注册 native messaging host、调用真实提供方、打印或提交 Amazon。

## 最终执行顺序

所有实现、正式测试和本说明先提交为干净源码 S；以下是 PowerShell 参数示例，父任务应为 run 使用一个尚不存在的唯一名称。`$repo` 是仓库绝对路径，`$run` 的父目录 artifacts 已存在。

```powershell
$repo = 'C:\Users\12079\OneDrive\Desktop\亚马逊Haul普品\RED-独立上架中台'
$run = Join-Path $repo 'artifacts/release-verification-<source-short>-<unique-run>'
node (Join-Path $repo 'scripts/snapshot-release.mjs') --source-repo $repo --output $run
$snapshot = Join-Path $run 'source'
$candidate = Join-Path $run 'candidate'
node (Join-Path $snapshot 'scripts/package.mjs') --source-repo $repo --snapshot $snapshot --output $candidate
node (Join-Path $snapshot 'scripts/verify-package.mjs') --source-repo $repo --snapshot $snapshot --package-root $candidate
node (Join-Path $snapshot 'scripts/e2e-release-candidate.mjs') --source-repo $repo --snapshot $snapshot --package-root $candidate --output (Join-Path $run 'runtime')
```

不要预创建 run/candidate/runtime。不使用默认固定 release 路径。snapshot build 失败日志写 run/build.log，成功回执为 source/.release-build.json；候选摘要为 candidate/版本与摘要.json，包外 receipt 为 run/candidate-receipt.json；runtime/report.json 与截图为实际候选证据。

最终实际候选验收目前待父任务执行。随后记录结果的文档提交 R、集成 merge M 引用实际 S，不能把 R/M 写回该候选冒充构建来源。若代码改动产生新 S，重新构建新的独立候选。新包保持“未启用”；真实店铺、供应商、付费服务、打印与正式入口切换均不在本次范围。
