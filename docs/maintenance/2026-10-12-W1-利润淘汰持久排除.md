# W1 利润淘汰持久排除与互斥分类

## 根因与实现

旧队列在验证利润结果前，按整个 rulesStamp、sourceStamp、recipeStamp 和 draft.revision 判为过期，并默认恢复 eligible=true。因此无关规则、标题、图片或草稿修订可绕开历史利润淘汰；销售件数改变生成新 recipe key 时也可脱离旧记录。

新增主进程只读 `AmazonService.previewPricing(draftId, sourceSnapshot, currentRecipe?)`：显式传入来源快照，复用既有成本币种、销售数量、包装依据与报价函数，仅在本地计算当前报价；不调用隐式 WorkspaceStore.getProduct，不保存草稿、不发远程请求、不分配销售身份。先校验原定价证据，保留人工填写的数量/包装输入；未改动的程序生成输入从当前来源/包装默认规则重新计算。返回的是临时定价投影，不能整份保存为原草稿。

利润队列不再用上述全局版本变化作为重试授权。只有 `qualifiedPricing` 确认当前完整定价证据和有效报价后才给出资格；成本/运费/售价上限/数量/包装实际变化但仍不合格，继续排除。缺失、冲突、无效证据分别保留资料/异常语义，不伪造业务淘汰。相同来源组件集合的数量变化即使改变 recipe key，也先经过该门禁。

旧任务的 SCREENED 行仍保持原状，startAuthorized/pump 不会重置它们。原结果、请求、草稿 ID、图片、尝试次数不变。W2 适配可调用同一本地 API 判断资格，但 W1 不实现或代为执行适配。

持久化继续兼容经过原 records.ts 校验的 SCREENED/RULE_FILTERED 结构；展示投影把 SKU_SELECTION_FILTERED、带定价证据的利润淘汰、其他规则淘汰分开。队列显式列出未选中来源规格，统计不再把这些项计入利润或其他规则淘汰。所有任务状态互斥计数一次，不通过重建历史任务改分类。

## 只读历史证据

读取本地 batch-summary-20261012/live.json 与 selection-audit-20261012/live.json 的结构和聚合信息；未修改原文件，未复制原响应、图片或识别信息到版本库。前者 103 个历史销售 SKU 的新展示投影：60 本次未选中、15 利润淘汰（14 ROI_MAX_PRICE、1 ROI_PROMOTION_OR_MARGIN）、18 系统待修复、1 待补资料、5 结果待核对、3 已提交待回读、1 标签；互斥合计 103。15 个利润报告均为 v2 business_blocked。
