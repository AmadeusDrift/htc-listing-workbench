## 暂停协议

| 情况 | 本次验证的行为 |
| --- | --- |
| task pause/cancel | 撤销该任务后续执行权限；不再开始备货/标签、付费或正式提交；已发送 PUT 的 ACCEPTED 回执仍保存 |
| 已排期的 accepted-only Followup | 独立只读生命周期可继续；单任务暂停不暂停整个店铺的 Followup |
| 维护暂停 | 阻止新 due 及 beforeSend；已发送的 GET 可以完成，但不开始下一个 SKU |
| UNKNOWN/SUBMITTING | 自动排期不 GET/PUT；显式人工 GET 允许读取，但不清未知锁，也不给备货资格 |
| 关闭并重建 | PAUSED/CANCELLED 和排队标签的停止状态保留，不恢复已撤销 task grant |

after-response 检查只核对请求归属，未重复调用包含维护暂停检查的 `beforeSend`。

以下阶段组合使用显式本地检查点，测试代码有注释，不等于从七图准备开始的端到端流程：

- late ACCEPTED：真实未提交草稿和真实 Execution.create 建立任务，以 Automatic 的 WAITING/READBACK 所有权检查点关联该 executionTaskId。真实 Execution 公共 startAuthorized 运行上传、URL 填入、校验、preview、正式 PUT；PUT 在 external fetch 挂起期间调用 Automatic.pause/cancel，真实 stopChildren 停止 Execution。释放 ACCEPTED 后保留回执，后续没有回读、备货、标签或重发。continue 正向控制完成 GET→备货→标签 PDF。该测试验证所有权停止和真实 Execution 返回处理，不声称覆盖 Automatic.prepareItem 等待 Execution 返回的每个分支。
- SUBMITTING：通过真实 persistence.beginWrite 建立持久写入意图检查点，验证自动不读、人工 GET 不解锁与重建，不模拟真实进程强杀。
