# 2.5.0 文案疑难升级验证（2026-10-13）

范围：API-R2 / C-060 / A19，W05/W06 的常规文案复核到冻结疑难目标；基线 f6d0ed9，独立分支 feat/htc-250-copy-review。仅合成数据库和 fake transport，不访问真实业务库、不启动正式 APP、不发付费 AI/Amazon/FTP 请求、不发布。

## 实现

- `AiService.listingFields` 的候选复核和 `reviewCurrentListing` 的当前文案复核接入同一持久化协调器。首个执行冻结普通用途及其 upgrade 配置；`UNSUPPORTED` / `CONTRADICTED` 项或 claim 提供具体原因时，普通非 PASS 结果最多升级一次。仅有普通编辑意见不会无条件触发升级。
- 新表 `ai_copy_review_upgrades(id,record_json)` 保存不可混用的 context/scope、冻结用途、普通与疑难 call/result 身份、sent、reason 和 completion 绑定。validator `validateCopyReviewUpgrade`，严格读取 `copyReviewResult`，跨表审计 `assertCopyReviewHistory`。原始两份 AiResult/AiCall 和 usage ledger 各自保留，最终返回实际产生结论的模型结果。
- 复核调用仍经原 `AiService.start`，复用原预算预占和结果事务的 durable callbacks。`DurableFieldCall.assignments` 改为可选，文案复核不伪造 W06 字段分组元数据；字段生成原分组数组、来源结果和组装合同未修改。
- CompletionRound 的 `review.callId/resultId` 保留普通请求所有权，`reviewFinalResultId` 通过同事务收据链接疑难结果。采纳和历史验证核对最终结果，原两个修复轮次和每步骤三次请求上限不重置；普通重试债务达到三次时不升级。不重复发送已成功候选。
- Luna、Sol、Astra、native DeepSeek 均按冻结目标及其实际渠道取 key，没有目标、渠道未启用/未配置、不支持聊天 JSON 均明确报原因，不临时换模型。疑难目标的 further upgrade 引用不继续执行。
- 第一次结果后进程断裂、取消、最终采用前断裂复用原链。已发送但没有可验证结果的升级调用保持未知并阻断，不能当 PASS 或重发。兼容 W08 的原 Batch 身份恢复谓词 `batchTasks.find(callId)`，仅已有原 Batch 可重入 start 由 runtime 校验/回收，不能新建付费请求。
- 本地事实、当前文案证据和 Schema 仍是既有最终 gate，不允许疑难 PASS 抹掉本地拒绝。原/目标结果不互相覆盖或伪造第一模型说过第二结论。

## 持久化与恢复

按主进程统一安排注册 Schema28 `image-reference-pins` 建表占位及 Schema29 `copy-review-upgrades`；本分支仅新增复核表 M07/ai owner、record-json 和备份白名单/严格验证。Schema28 pin 的领域 validator 由主进程原 W07 接线负责合并去重。

`retainCopyReviewHistory` 保留前后快照已发送身份和费用事实，恢复旧备份时不导入后生成的商品结论；缺失结果链接保持 null，执行明确阻断。最终复核链接和原 call/result 强所有权分别校验。旧版本迁移夹具删除两个新增表，不放宽旧版结构白名单；literal legacy 图片夹具移除当年不存在的用途/升级 sidecar，原响应内容保持原测试意图。

## A20 只读核对

`adapters/openrouter-decisions.ts` 实际调用 `/api/alpha/decisions`，发送 `state`、`questions`，支持 choice/noul/score，校验返回问题键与结果范围。`AiService.categoryAnalyze(select)` 已接 `category_decision`。`enum_decision` 目前只有用途配置，未发现实际业务执行调用点。

仍缺实用的受限枚举端口：一次请求内为需要独立判断的候选构造多个问题；问题 ID 明确绑定原 Schema 枚举值和来源快照；阈值和 unknown 口径明确；多选结果集合交原 Schema 的 oneOf/anyOf/not 等互斥/组合约束最终验证。应只在现有补全确需疑难枚举时调用，不能让每个 enum 无条件多收一次费用。本分支未修改 enum 付费路径，未宣称 A20 已完成。

## 未验证与合并注意

真实账户模型能力、当天 OpenRouter/native DeepSeek 请求参数、真实费用、Batch 线上往返均未验证。W08 分支的 Batch runtime 实际合并联测由主进程进行；本分支的两个复核入口均使用原 start，未修改 start 主体。复杂 review 已收到但本地解析失败时沿用明确阻断，不猜测修复后重复收费。测试日志在独立 worktree 的 .test-data 下，未把合成临时数据库提交版本库。

## 最终补充验证

- 当前文案的显式新复核保留既有语义：已完成执行可创建独立新复核，较新否定结论仍能废止旧 PASS；只有未完成链复用原 call。ImageWorkflow.cachedCopy 对待升级的 first 不当作最终复核结果，回原 current-copy 入口接续，避免先进入文案修复。
- 扩展 282 项合成测试首轮为 272 通过 / 10 失败：8 个 literal-legacy fixture 问题和上述 2 个 current-copy 语义问题均已定位并修复。失败的全部 10 项加新增真实 ImageWorkflow pending-upgrade 路由测试，11/11 重新通过，日志 `.test-data/copy-review-legacy-recheck.log`。不把首轮失败写成全绿。
- 新增候选缓存原始字节身份检查；同 suggestionId 改写 candidate 内容必须拒绝，不能复用原 PASS。
- 最终专项为 18 项；与 CompletionJournal 及 W06 群组回归共同 49/49 通过，日志 `.test-data/copy-review-final.log`。新增 ImageWorkflow 恢复测试使用真实工作流与 fake 传输，将已有字段完成阶段隔离，并在生成图片前停止；确认 pending 升级路由进入原复核而不是 repair。
