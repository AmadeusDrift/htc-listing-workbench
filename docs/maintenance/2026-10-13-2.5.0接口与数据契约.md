# HTC 2.5.0 接口与数据契约

日期：2026-10-13。配套[完整实施方案](2026-10-13-2.5.0完整实施方案.md)。本文是实现时遵守的技术规格；接口名为本轮整理后的目标名，不冒充现有 API。可因现有类型适配调整命名，但职责、版本和副作用边界不能改变。

**最新规则C-060：** 现役AI入口只有OpenRouter、DeepSeek独立密钥、阿里；无OpenAI官方直连、无旧图像中转运行入口。新增Batch与逐用途选模/思考契约，旧接口研究与历史保留条件被本版覆盖；原文/费用/图片/预算的只读兼容仍有效。

## 1. 依赖规则

同一 Electron 程序、一个本地 SQLite 工作区、受控文件目录。renderer → preload 白名单 IPC → 应用命令/查询 → 领域接口。领域内可保留现有函数和记录，不按每张表建一层服务；不引入微服务、事件总线或第二工作流平台。

- main 入口负责装配；`src/main/application/` 仅协调跨领域事务、变更影响和恢复，不实现分类/报价/图片规则。
- `src/shared/` 只放可序列化契约及无 I/O 的规则，不依赖 main/renderer。
- 模块通过 `public.ts` 或明确的 `ports.ts` 暴露接口。迁移期旧 service facade 可以转调，必须注明删除条件；不得新建第二条行为分支。
- M07 AI 不导入 Listing/图片的解析校验实现；M09 素材不决定销售适用性。M11 不直接写草稿、图片或请求结果。
- M06/M08 间的修复和重核由应用层顺序协调；不互调 service 形成循环。模块事件使用返回结果，不以事件总线替代事务。
- 整理边界是逻辑所有权，不强制把 `amazon` 目录所有文件搬走。平台 transport/vault 可复用，但领域不能将全部操作塞回 `AmazonService`。

## 2. 公共引用、问题与导航契约

新增 `src/shared/workflow-context-contracts.ts`，以下为自包含的目标类型草案，可与现有 JsonValue 统一导出后使用：

```ts
export type ModuleId = 'source' | 'product' | 'sales' | 'pricing' | 'catalog'
  | 'listing' | 'ai' | 'images' | 'assets' | 'publish' | 'tasks'
  | 'observations' | 'procurement' | 'labels' | 'documents';
export type Json = null | boolean | number | string | Json[] | { [key: string]: Json };
export interface Ref {
  owner: ModuleId;
  id: string;
  revision: string; // 不把不同模块的数字 revision/哈希混算；明确序列化为稳定字符串
}
export interface TargetScope {
  targetId: string;
  sellerId: string;
  marketplaceId: string;
  mode: 'live' | 'demo';
}
export interface ListingContext {
  productId: string;
  sourceVersion?: Ref; // 旧记录无法还原时允许缺失，不能伪造
  sourceVariantIds: string[];
  salesPlan?: Ref;
  sku?: string;
  target?: TargetScope;
  draft?: Ref;
  task?: Ref;
  taskItemKey?: string;
  operation?: Ref;
}
export type Stage = 'source' | 'classification' | 'schema' | 'pricing' | 'fields'
  | 'generation' | 'download' | 'review' | 'adoption' | 'hosting'
  | 'validation' | 'submission' | 'readback' | 'labels' | 'backup';
export type IssueLocation =
  | { kind: 'field'; pointer: string; label: string; relatedPointers: string[] }
  | { kind: 'image-slot'; runId: string; slotId: string }
  | { kind: 'source-variant'; variantId: string }
  | { kind: 'request'; requestId?: string }
  | { kind: 'unknown'; reason: string };
export type IssueAction =
  | 'edit-source' | 'edit-draft' | 'inspect-evidence' | 'resume-download'
  | 'review-original-submission' | 'open-connection' | 'continue-original-task';
export interface BusinessIssue {
  id: string;
  owner: ModuleId;
  context: ListingContext;
  stage: Stage;
  code: string;
  kind: 'needs-input' | 'platform-rejection' | 'system-failure' | 'unknown-result';
  summary: string;
  locations: IssueLocation[];
  evidenceRefs: Ref[];
  allowedActions: IssueAction[]; // 所有者当前判定，UI 不能自己推导写入资格
  status: 'open' | 'resolved' | 'superseded';
  observedAt: string;
  rawMessage?: string; // 已脱敏的必要原文，不含凭据
}
export interface ReturnContext {
  view: string;
  selectedRecordId?: string;
  filter: Record<string, string>;
  search: string;
  expandedKeys: string[];
  scrollAnchor?: string;
}
export interface OpenContext {
  target: ListingContext;
  issueId?: string;
  location?: IssueLocation;
  returnTo: ReturnContext;
}
export type CommandResult<T> =
  | { kind: 'done'; value: T; changedRefs: Ref[]; issues: BusinessIssue[] }
  | { kind: 'waiting'; operation: Ref; reason: string; nextCheckAt?: string }
  | { kind: 'rejected'; issues: BusinessIssue[] }
  | { kind: 'revision-conflict'; current: Ref; message: string };
```

约束：字段路径用结构化 JSON Pointer，中文名仅展示；数组路径还需稳定项身份/原快照定位验证，不能在数组重排后跳错行。具体词条范围只有证据能定位时提供，不能让 UI 猜坐标。错误属于多个字段时保留全部路径，属于请求时不伪装单字段。

`OpenContext` 仅是导航，不创建草稿、不移动分区、不发请求。目标不存在返回明确状态；不得 `requestedDraft ?? firstDraft`。返回时恢复界面位置但重新读取最新业务版本。失效旧链接不改变目标身份。

## 3. 各模块输入、输出与写入者

下面的方法均通过现有服务适配后逐步收敛。方法中“保存”不暗含继续任务/发布；外部调用必须显式命令。

|---|---|---|---|
| M01 `SourcePort.sync/getSnapshot` | 同步账号、范围、增量/全量模式、cursor | 原始记录版本、规范化来源、逐项获取状态 | 只写来源/同步；同账号可信商品标识归并，缺标识按采集记录分开 |
| M02 `ProductPort.receiveSource` | 来源版本及原文/规格/图片关联 | 新建/采用/复用/保留待采用、本地商品引用 | M02 写主档；M01 记录回执；获取成功不等于接收成功 |
| M02 `readSnapshot/compareSource/previewAdoption/adoptSource` | 商品、期望revision、整链接来源版本、明确采用命令 | 差异、人工保护、受影响对象、采用版本 | 预览只读；采用检查冻结/版本，不能静默覆盖人工值或提交快照 |
| M03 `SalesPort.plan/allocateIdentity` | 固定商品版本、目标、配方约束/命名模板 | 配方组件/数量/成本及稳定 SKU 引用 | 预览不占号；占号与命名账本同事务；重试/取消不回收 |

| M05 `CategoryPort.classify/SchemaPort.ensure` | 来源/目标/分类依据、有效人工选择、Schema scope、原操作引用 | 真实产品类型、规则快照、等待或错误、剩余既定GET预算 | 显示规则与实质规则变化区分；刷新不覆盖旧草稿；失败不重复AI |
| M06 `ListingPort.create/read/save/parseCandidate/validate/adopt` | source/sales/schema引用、native JSON、expectedRevision、候选收据 | 草稿/候选/问题、影响集、当前引用 | 统一 initial/repair/recovery 解析采用；保存不提交，不能用显示字符串代替原生值 |
| M07 `AiPort.request/reconcile/readReceipt` | owner业务操作、轮次/步骤、输入引用/哈希、配置快照、输出模式 | 持久化请求/原始响应/usage、等待或传输阶段错误 | 请求去重仅同业务身份；不负责领域通过，不擅自选择供应商重试 |
| M07 `BatchPort.previewPlan/submit/read/reconcile` | 任务模式、已就绪操作、逐用途配置快照、custom_id映射 | 远端批次收据/等待状态、逐项结果/费用及缺失原因 | M07只写远端批次账；TaskPort决定采用/继续，不能由批次completed直接标上架成功 |
| M07 `PurposeRoutingPort.read/save/resolve` | 用途ID、gateway/model/思考/升级配置、expectedRevision | 能力检查与有效请求快照、不可用原因 | 只改目标用途；可复制模板但无共享可变绑定，不能互相覆盖 |
| M08 `ImagePort.plan/continueSlot/review/adopt` | 商品/配方/草稿版本、slot、原候选及既定预算 | 图位结果、复核记录、采用引用、修复请求 | 只写图片业务；错误图局部处理，通过图保留；未知不标通过 |
| M09 `AssetPort.ensureOriginal/materialize/store/upload` | 来源链接/响应blob引用、哈希/目标目录、hosting profile版本 | 文件版本/hash/格式/下载或托管收据 | 不判销售适用性；字节去重不等于跨SKU审核可复用；失败保留来源收据 |
| M10 `PublishPort.prepare/validatePreview/submit/reconcile` | 不可变发送快照、原授权、目标/SKU写锁、报价/规则依据 | 意图、结果收据、未知状态、操作引用 | 手动/自动共用；发送前再次核对依赖，UNKNOWN不得普通重发 |
| M11 `TaskPort.create/read/pause/continue/cancel/applyResult` | 创建范围/授权、模块操作引用及结果版本 | 批次/逐销售SKU状态和计数投影 | 唯一任务写入者；结果CAS防重复推进；不反写其他表 |
| M12 `ObservationPort.schedule/read/refresh` | HTC接受/跟踪账本、目标SKU、观察类型/时间范围 | 观察值及来源时间、未获取/过期/失败状态 | 失败保留旧成功值；不把观察当发送收据或解除未知锁 |
| M13 `ProcurementPort.create/revise` | 已接受身份/平台观察、配方版本、人工数量价格 | 采购单修订、展开采购件/包数 | 不回写配方、原价和SKU；改采购价撤销对应确认 |
| M13 `LabelPort.prepare/export` | 已保存批次修订、销售单位数、格式与平台资格 | label版本/hash/READY及原因 | 按需准备且复用匹配PDF；READY/OPENED不等于PRINTED |
| M13 `ShipmentPort.associate/importDocument` | 人工货件号、PDF、批次引用 | 本地附件及关联身份 | 显式人工关联未核验；旧附件保留，不暗示发货/入库 |
| T02 `MaintenancePort.backup/restore/previewRetention/applyRetention` | 模块清单/受保护引用、备份格式、明示命令 | 可恢复备份、恢复报告、清理计划/结果 | 清理执行重验引用/版本；备份失败不覆盖上一个成功文件 |

模块设置保存统一 `section + expectedRevision + patch`；从所有者当前值合并并验证，只提交本分区字段。原 `saveListingRules` 保留兼容入口但不得把旧表单全量覆盖新配置。业务相关依赖按内容哈希判定，UI保存不生成新业务授权。

| `amazon_settings` 等共享表 | 按键前缀/记录类型划给上述所有者 | 表相同不代表共享写权限 |

新增物理数据建议沿现有严格 record_json + 可查询索引方式，而非把所有领域状态放一个通用“大记录表”。初次迁移如仍基于Schema21，后续编号从22顺序分配，不跳号或覆盖他人迁移：

- `source_snapshots`（M01）：账号/原始商品身份/外部记录/来源版本、原文hash、取得时间；原回执保留。
- `product_source_adoptions`、`product_fact_scopes`（M02）：采用/冻结依据及common/variant/unknown范围；旧无法映射数据使用明确 legacy引用，不补造来源时间。
- `ai_provider_receipts`（M07）：request/call/owner、阶段、文件引用、原响应hash、usage；大响应放受控文件，不嵌入多个大JSON副本。
- `asset_materializations`（M09）：稳定来源收据/下载身份、文件hash、状态和恢复点。
- `schema_fetch_operations`（M05）：迁入已有任务行GET预算；旧记录原文留存、建立唯一映射，不能双计/重置。
- `asset_references`（M09维护投影）：引用者owner/id/revision + assetVersion；领域仍是语义真相。清理前向所有者重验，不能仅看可能过时索引。
- `module_migration_journal`（T02）：迁移批次/原版本/结果/失败恢复信息；不承载业务进度。
- `ai_purpose_profiles`（M07）：每用途独立版本、gateway/model/思考与疑难目标，旧偏好映射来源；不得保存明文Key。
- `ai_batches`、`ai_batch_items`（M07）：本地意图/指纹、workspace/credential非敏感引用、remote ID、状态/成本；逐custom_id对应原operation/attempt/输入版本/收据/采用状态，唯一约束阻止双扣与双采用。

新表是否可复用等价现有结构先在实施任务W02登记，要求避免两份可变真相。相关新旧reader、validator、backup manifest和索引在同一工作包接通。

## 5. 事务、结果保存与恢复顺序

跨模块本地提交用同一个 `DatabaseSync` / 受控事务上下文。`transaction(work)` 仅接受同步回调，遇到 Promise 直接拒绝；模块内部参与同一事务时不再 `BEGIN`。外部网络等待绝不放在持有数据库事务的回调中。

```text
本地命令：校验 expectedRevision → 同一事务调用各所有者写入 → 审计 → COMMIT
原图/响应文件：唯一临时文件 → 完成hash与格式检查 → 同盘原子rename → 同事务登记引用
外部请求：持久化意图/配置/业务授权及预算 → COMMIT → 发请求
          → 响应最早阶段保存通用收据/受控原文或字节
          → 后续下载/解析/校验 → 明确采用 → 任务结果CAS推进
重启：按原operation/request ID查收据 → 恢复缺失步骤 → 仅原授权允许时继续
```

文件与数据库不伪装成真正同事务：崩溃后的孤立临时/已命名文件由恢复日志识别；有引用的缺文件标损坏并阻断相应采用；不会伪造文件存在。文件落盘失败保留已知供应商请求状态，不能把“已发未记完整响应”回退成未发送。

PAUSED/CANCELLED 允许保存已发请求的晚到响应与费用；采用/新发送前重新检查任务授权、版本及暂停状态。模型切换只改变后续新请求配置，旧操作不会重新开户。未知AI结果按既有有限恢复规则处理，未知Amazon写入仍不盲重发，两者不可共用简单重试策略。

## 6. API-R2：现役入口、逐用途模型与Batch

### 6.1 入口与协议

| gateway | 用途/地址 | 约束 |
|---|---|---|
| `openrouter` | 文案/复核：`https://openrouter.ai/api/v1/chat/completions` | messages + response_format + 模型支持的reasoning；GPT模型统一走此网关 |
| `openrouter` | 生图：`https://openrouter.ai/api/v1/images` | prompt/input_references、端点实际支持参数；返回base64原文先保存 |
| `openrouter` | 决策：`https://openrouter.ai/api/alpha/decisions` | state + questions对象；answers对象，choice/noul/score，不套官方直连字段 |
| `openrouter` | Batch：`https://openrouter.ai/api/v1/batches`及`/:id` | create/read/list独立适配；基础模型ID和异步endpoint，不是把`:batch`塞同步chat |
| `deepseek` | 保留独立Key及现有 `https://api.deepseek.com` 适配 | 与OpenRouter同一用途选择器；模型/思考按该协议转换，不把Key转发给OpenRouter |
| `aliyun` | 现有OCR/图片风险等服务接口 | 原有独立凭据/计量/开关，不能用GPT模型选择覆盖服务身份 |

本地活跃gateway枚举不含`openai-direct`、`tyai`/旧relay；历史枚举可解析但无发送能力。图床/FTP不属于生图中转站，仍保留素材托管能力。删除直连指运行客户端/凭据页/请求入口，不删除OpenRouter中`openai/*`模型或上游provider名。

来源：[OpenRouter文本](https://openrouter.ai/docs/quickstart)、[图像](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)、[Decisions](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)。文档字段需按实际能力验证，未调用真实账号。

### 6.2 文案相关用途矩阵

以下每一行独立保存模型与思考配置。标题、五点、描述等文案类型也提供独立覆盖；默认从通用配置复制初值。相同模型/思考且输出合同允许时可合并调用，不同配置必须分别执行，不能为省调用强行共用一个模型。新增文案调用必须登记purpose，禁止落入无法追踪的通用catch-all。

| purposeId | 类型 | 可选范围/能力条件 |
|---|---|---|
| `source_understanding` | 来源文本/规格理解 | Luna/Sol/Astra/DeepSeek；带图时需视觉能力 |
| `category_analysis` | 类目文字分析、候选解释或疑难判断 | 同上；不替代专用Decisions的原始决策结果 |
| `listing_generation` | 初始文案生成的通用默认 | 同上，作为各文案类型默认来源，不覆盖已单独设置项 |
| `listing_title` | 商品标题 | 同上，可独立于其他文案型号/思考 |
| `listing_bullets` | 五点描述 | 同上，五点作为同一内容类型，保留独立选择 |
| `listing_description` | 详细描述 | 同上，不强制继承标题配置 |
| `listing_search_terms` | 适用的搜索词/后台关键词 | 同上；仅Schema/业务需要时调用，不新增必须填写的要求 |
| `listing_completion` | 缺失字段补全 | 同上，原生字段结构必须保留 |
| `listing_repair` | 平台拒绝/冲突后的定向修复 | 同上，正确/人工字段保护 |
| `copy_review` | 常规文案复核 | 同上，独立于生成模型 |
| `copy_review_difficult` | 文案疑难/异常复核 | 同上，作为配置的自动升级目标 |
| `image_plan` | 七图方案/提示词生成 | 同上，商品依据与渲染要求区分 |
| `image_plan_repair` | 图像方案/文案联动修复 | 同上，独立可选 |
| `image_text_review` | OCR结果/图中文字核对 | 文字可用适配模型，直接看图时需视觉；不替换阿里OCR |
| `appearance_review` | 商品外观一致性文字结论 | 要求输入图片能力及结果Schema |
| `appearance_review_difficult` | 外观疑难复核 | 同上，独立升级目标 |

设置至少列出 `openai/gpt-6-luna`、`openai/gpt-6.1-sol`、`openai/gpt-6-astra`；DeepSeek输入自身Key后列其可用型号。能力不合的型号说明原因而不假装可用，也不自动换模型。旧Luna常规/Sol疑难只作默认意图，不是硬编码。Astra可被用户直接选用于任何合适用途，不意味着所有疑难都自动升Astra。

专用 `category_decision` / `enum_decision` 仍选择可用的Decisions模型，不把Luna/Sol/Astra聊天型号伪装Decisions端点；需要生成解释时使用上表对应用途。生图选择OpenRouter图像型号，不放入文案模型选单。

```ts
export type ActiveGateway = 'openrouter' | 'deepseek' | 'aliyun';
export type ListingExecutionMode = 'immediate' | 'deferred_batch';
export interface AiModelSelection {
  gateway: 'openrouter' | 'deepseek';
  credentialRef: string;
  modelId: string;
  reasoning: { enabled: boolean; effort: string | null };
  capabilityRevision: string;
}
export interface AiPurposeProfile {
  purposeId: string; // 必须命中用途注册表，不能是任意不可追溯字符串
  revision: number;
  primary: AiModelSelection;
  escalationPurposeId: string | null; // 指向已登记的疑难用途，模型只在目标用途保存一次
}
export interface AiExecutionSnapshot {
  purposeId: string;
  profileRevision: number;
  chosen: AiModelSelection;
  requestedMode: ListingExecutionMode;
  effectiveMode: 'sync' | 'batch';
  nonBatchReason: string | null;
  inputFingerprint: string;
  requestedEffort: string | null;

```

每用途设置独立patch+revision；可复制初值但不共用可变对象。疑难模型只在目标用途保存一次，其他行引用其purposeId，拒绝自引用/循环；本次执行将目标型号/思考/版本一起冻结，避免升级时临时读到另一套配置。新操作冻结快照，改全局不改变已排队批次或已发送请求；已有任务只在明确采用配置变更后影响尚未发送部分，不重新跑成功结果。

DeepSeek思考参数按自身模型能力处理：当前文档区分开关与low/high/max等实际档位，并有兼容映射。UI显示实际可选档位，旧medium等导入时记录映射并提示，不显示“medium”实际却无说明地执行high。[DeepSeek思考文档](https://api-docs.deepseek.com/guides/thinking_mode/)。OpenRouter能力也逐模型/端点/同步或Batch核对，不把某家参数枚举当全局规范。[Astra目录](https://openrouter.ai/openai/gpt-6-astra)。

### 6.3 延迟批量的产品语义

自动上架创建任务时显示`immediate`或`deferred_batch`，默认即时；旧任务缺该字段按即时解释，不自动转成Batch。创建时保存模式/覆盖计划：即时逐步调用；延迟对能力满足的就绪AI请求分阶段组Batch，其他步骤按原接口执行并列明原因。当前生图/Decisions/阿里和DeepSeek直连不冒充OpenRouter Batch；不能为省钱静默替换服务。若全流程没有任何可Batch步骤，延迟选项禁用且给出可调整的模型/能力原因。

延迟模式不是定时发布，不保证某个钟点上线。每个批次结果被领域校验/采用后才推进依赖步骤，可能形成多轮Batch；最终Amazon验证/提交仍走M10且受原锁和授权控制。启动摘要说明混合执行和费用范围，用户原整批授权允许在APP持续运行且任务状态允许时自动推进，不每批要求点击。暂停/取消/重启后的授权规则保持原约定。

### 6.4 远端事实与本地设计

**已核对平台事实（2026-10-13）：** Batch支持chat/responses/messages/embeddings，当前无images/Decisions端点；窗口24h；同批同模型，项目custom_id唯一；结果在completed时随GET内联，失败/过期/取消状态可能无结果；图像输入需可读URL；请求顶层元数据在requests前；provider参数不同于同步；输入/结果平台保留期有限。使用当前`/api/v1/batches`，不抄旧beta示例。[Batch文档](https://openrouter.ai/docs/batch-quickstart)。Luna、Sol、Astra有批量目录条目，但运行仍需核账号/端点能力：[Luna Batch](https://openrouter.ai/openai/gpt-6-luna:batch)、[Sol Batch](https://openrouter.ai/openai/gpt-6.1-sol:batch)、[Astra Batch](https://openrouter.ai/openai/gpt-6-astra:batch)。

**HTC具体实现设计（不是平台保证）：**

1. M11提供已就绪的业务请求；M07按`taskId + phase + purpose + gateway/model + reasoning + schemaFingerprint + provider + credentials`分组，按已验证上限分块。不要跨不同本地任务合成一个难以取消/归因的远端批次。
2. 创建前同事务保存本地批次意图/指纹、逐custom_id到原operation/attempt映射及预占；HTTP后立即存remote ID。custom_id用不泄露商品内容的稳定标识，不能凭返回数组顺序对SKU。
3. 202仅`submitted/validating`；poll不另占生成轮次。GET失败只重查，不重POST；创建超时无ID设`submission_unknown`，使用可信账户scope、时间/内容指纹及可获取项核对，无法唯一定位就保持待核对。公开协议未证明请求幂等Key时不能宣称“重POST一定去重”。
4. 每次回收先保存原批响应，再核对custom_id完整性/重复/外来项；按领域原版本解析/校验/采用，业务结果与TaskPort推进CAS。批次completed可含item error，不能整体标成功。只有明确未执行或允许续试的失败项才创建新尝试，不能重发整批。
5. 本地状态建议`prepared → submitting → submitted → waiting → collecting → reconciled`；另有`submission_unknown`、`failed`、`expired`、`locally_stopped`。远端原status单独保存，不能用本地停止伪装cancelled。
6. 本地暂停/取消仍可抓取已发送结果/记账，但禁止新批、自动采用或平台发布；不实现未证实的远端cancel路径。终态DELETE不是取消且不在自动清理里默认调用。APP关闭后远端可能继续，重开先重连已有remote ID，明确继续后恢复业务推进。
7. M09为视觉Batch准备版本化参考URL及保留pin，必须覆盖等待/取回期；引用来源/候选图用途独立于上架采用。URL失效不自动换源；不能把inline base64当Batch URL。无可靠托管的视觉步骤标普通或待配置，启动摘要如实显示。
8. 返回时资料/草稿/model版本可能已变：保存原结果及费用，标待重核/未采用，不覆盖当前人工内容。改即时模式仅影响尚未发送且明确采用变更的步骤；在途/未知Batch不再同步发送一遍。
9. 批次/逐项usage分开：批总额若无逐项成本，按明确方法估算分摊并标estimate；不能伪造实际逐SKU成本，合计只入账一次。失败/无结果也不能从状态推断费用为零。充值费单独，不重复加。
10. `ai_batches/items`、provider receipt、托管引用和使用量随备份保留。恢复旧库合并后续remote ID/意图/项目账本，防止重复提交；平台结果需及时归档本地，过期不可取时明确提示，不能重跑伪装恢复。
11. 长时间等待后，在新收费步骤/最终发布前重新核对实际价格及促销有效期、Schema/目标/连接和任务授权。不能用排队时通过的检查直接发送已失效资料，不静默延长人工促销日期或改人工报价；按已有变更影响规则处理并保留Batch成果。

BatchPort至少含`previewPlan(taskRef,purposeSnapshots)`、`submit(localBatchId)`、`read(remoteBatchId)`、`reconcile(localBatchId)`、`stopLocally(localBatchId)`；停止返回本地/远端状态分别说明。list仅用于所属workspace的本地已知批次核对，不能把其他Key或应用批次当HTC费用。型别/上限/路由provider字段在能力缓存更新时验证，不默默丢不支持的参数。

### 6.5 共用记账、升级与历史约束

请求身份仍是operation/step/attempt/输入/配置快照，不因Batch改成一个大包就丢逐项预算。升级触发保留具体冲突/不确定原因，目标读purpose profile；一次常规→已配置疑难目标保持原轮次限制，不形成Luna/Sol/Astra/DeepSeek循环。改变供应商或思考强度不重置预算。

新OpenRouter文本/图片、DeepSeek输出全部先保存receipt再由领域采用；旧中转URL只作历史收据解释/原文件恢复，不能调用旧生成接口。凭据仅main vault持有，UI不接触Key。usage、已报告费用/估算/未知、充值费用各自记录，模式/模型/实际provider/思考/远端batchId一并可追踪。

## 8. 架构验收

- 现存值导入循环簇必须被拆开；共同契约/常量移中立模块，不能靠改成动态import隐藏循环。工具扫描需要识别re-export/dynamic及排除type-only，人工复核报告说明范围。
- main模块跨所有者SQL检查没有未登记写入；迁移/恢复必须使用受控注册接口，不能以“基础设施”为由新增全知业务层。
- M07新增一个provider不要求修改SKU、定价、采购；M04修改一项费用算法不要求修改AI prompt/image审核；M09下载恢复不重新请求生成。用接口/断点用例证明，不以目录变小作证明。
- UI读/导航路径不改变分区、身份、预算或业务采用；模块问题模型是唯一解释来源，renderer不得另写一套资格判断。
