## 实施

- 以 `fieldPurposeGroups` 为真实业务路由：完整 Schema Listing 补全/修复明确点名的缺失枚举字段，可以替代原聊天字段调用，使用 `enum_decision` 用途。普通 suggest 不自动触发，不给每个 enum 追加收费。
- 仅处理真实 Schema 可解析的标量或数组枚举，以及带 value / marketplace_id / language_tag 的标准数组包装；复杂不能安全构造的属性保留原路径。超过一次 200 questions 的字段不纳入本次 Decisions 分组。
- 已有属性、repair 当前值、业务固定值、程序关系字段、业务规则/计量/受保护字段、明确来源冲突不交枚举投票。单值枚举不交 AI。
- 单选是实际候选 choice，加独立依据是否充足的 choice；候选外返回由真实适配器拒绝。复选每个原枚举候选独立 yes/no/unknown choice，不使用概率阈值；任一 unknown 保留整个字段缺失，不能把 unknown 当 no。
- 结果构造原生 JSON 集合并通过既有候选校验与完整原始 Schema 编译验证（包括 oneOf/anyOf/not）。无关字段已有缺失不会阻断该候选，但候选字段错误及根级组合错误会阻断；后续 Listing 完整校验/平台预览继续生效。
- 不捏造引用原文、证据 ID 或人工确认；判断标记 infer，实际来源上下文随请求提供，服务原始答案保存在 receipts。原本的复核、人工值保护、实际报价资格和提交门禁不修改。
- 复用 AiService.start 原来的 request control / fresh / quote / purpose snapshot / receipt / ledger / completion journal；没有直接 fetch、Batch 冒充或备用模型静默切换。service 仅增加 import 与窄调用分派。
- enum 作为第七种字段用途组，两处组大小验证同步从 6 调整为 7；已有分组历史兼容。
- category 测试夹具更新为现役 select=OpenRouter Decisions、judge=OpenRouter chat。Decisions 网络结果未知时验证 unbounded usage，不再套聊天 max_tokens 预算断言。
