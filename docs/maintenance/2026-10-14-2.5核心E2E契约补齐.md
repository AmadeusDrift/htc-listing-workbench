## 隔离与证据

所有本组脚本均经过 `e2e-core-runtime.mjs`：启动应用入口前安装网络保护，独立 `.test-data` 数据目录；禁止 Node HTTP/HTTPS/TLS、DNS、fetch、WebSocket、Electron net/session 和外部浏览器请求。唯一 TCP/DNS 例外是数字回环地址，供真实本地 FTP mock 协议服务使用。生产脚本还保留 Windows safeStorage、真实 preload/IPC 与真实 renderer；AI/执行夹具使用合成响应。每次退出保存 `artifacts/core-e2e-logs/network.jsonl`，保护器非零意外请求会导致测试失败。

运行日志、截图、报告与数据库仅保留本地 `artifacts/`、`.test-data/`，不进入版本库。初次权限受限进程启动及 loopback 控制测试失败，后使用受审权限运行；最终结果只依据实际完成的重跑，不把初次失败记为通过。

## Haul 自动链

旧 pipeline 的演示 standard 草稿不代表当前 Haul 验收。现建立独立合成手动商品和假店铺凭据；Schema 是合成 Haul 支持规则，采购币种、包装尺寸重量和成本由 `seedAuthorityHaulPricing` 构造，实际报价及资格由生产算法计算，BZR 与 Haul 标志贯穿链路。

真实 preload/IPC、AutomaticListingService、ExecutionService、HostingService、AmazonService、FollowupService、ProcurementService、ItemLabelService 验证：原生取消零上传零提交；确认后本地 FTP 上传、URL 校验、假 Amazon 预览和一次提交、合成时间推进后的真实回读状态机、备货数量绑定；完成上架不请求标签，明确 prepare-labels 后才向假标签端点申请并验证 PDF。

边界：图像完成是受控测试边界；假 Amazon HTTP 和 Schema 不代表官方服务验收；此夹具为 main-service/IPC 集成窗口，不是生产 renderer。真正生产 renderer 由本组其余桌面脚本覆盖。没有真实 AI、Amazon、外部 FTP、打印或付费请求。
