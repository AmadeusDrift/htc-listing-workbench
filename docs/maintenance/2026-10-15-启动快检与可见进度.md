# 启动快检与可见进度（2026-10-15）

本项落实F03，按用户要求仅做相关基础验证。未操作真实任务、AppData、付费接口或平台；未重跑全量和Computer Use。

## 行为

- 先显示没有业务按钮、preload或IPC的启动窗口，依次显示退出状态核对、必要检查/完整检查、业务历史和服务初始化、界面加载；安全检查完成前没有业务窗口可提交。
- 正常退出时，必须所有业务服务正常关闭、现有业务历史完整校验通过、安全快照成功后，才能保存Windows安全存储加密的单次正常退出凭据。关闭失败、检查失败或快照失败均不生成凭据。
- 下一次启动先消费凭据，流式核对实际程序代码身份、Schema、数据库/WAL全部内容及上次安全快照内容；完全匹配才复用上次已验证的安全快照，省去启动时重复的完整检查和全库复制。
- 首次、异常退出、代码升级、备份恢复、库或快照改变、凭据缺失/无效、安全存储不可用一律回完整检查。升级后第一次启动仍会完整检查，正常退出后的下一次才能走快路径。
- **首次必要业务历史检查仍保留**，继续使用已有同启动、同数据版本的重复检查复用。运行期原请求身份、UNKNOWN、费用次数、迁移和正式提交保护不变，没有跨启动豁免业务校验。
- 不新增数据库表/迁移；凭据文件是工作区的`startup-clean.enc`，不含业务内容明文。缺失只影响启动速度，不清理业务记录。删除凭据可强制下一次全检，不需要恢复旧备份。

## 基础证据

- 启动会话3项、启动历史复用4项、安全快照5项，共12项相关短测试通过，约2.49秒。普通沙箱中旧文件替换测试遇到临时文件rename EPERM；同一12项仅正常权限复验一次后12/12通过，未修改断言。
- `npm run typecheck`通过；`npm run check:boundaries`退出0、sqlOwnershipErrors为空。
- 归档235MB数据库复制到本树独立`.test-data`后测得：完整检查与安全快照约2753毫秒；正常凭据流式核对约397毫秒；仍保留的首次必要历史检查约1008毫秒。仅组件计时，不是整个EXE启动时间，也不是10代i5实机结果。详细证据在忽略目录`artifacts/startup-round2/benchmark.json`。
- 不声称启动秒开、全链可售、真实拖窗或低配置整机验收通过。图片后台线程接线由主进程在图片提交合入后统一处理，本提交不改图片业务。
