# W3 旧未知检查点接续（2026-10-12）

范围：仅显式继续时恢复旧 `contentPreparation.STARTED` 缺 operationId 与自动行 `imageStarted` 缺工作流；不启动真实任务，不修改真实数据库、凭据或原始证据，不发 AI / Amazon 请求，不发布。

## 证据与实现

只读历史导出显示：67 有四个字段候选、两个 NEEDS_CHANGES 复核，未采纳；93-B 有一个候选及精确采纳回执；93-C 无保存字段结果；94-A/B 无字段结果和生成候选，原 imageAttempts=0。七份旧字段结果均通过原存储格式及调用所有权验证。私有导出不入库。

- 在原数据库事务内恢复/创建持久字段操作并回填旧工作流 operationId；已存在 ACTIVE 或精确匹配 DONE 操作直接重连。
- 候选必须有原调用、用量账本、产品/规格身份、冻结上下文哈希；采纳只认确切回执。原结果/调用/用量不改写，派生字段恢复结果不额外计为一轮。
- 最近可执行结果接回原两轮结构；更早轮数、全部已关联调用/结果/采纳 ID 单独保留。没有可验证结果的旧 STARTED 至少保留一次未知尝试债务；已绑定丢失调用按原数量计，单步骤最多三次。耗尽保留原因，不再派发。
- HTTP 成功但没有结果不视为采纳，按缺结果的有限预算处理。保存结果/采纳后崩溃，重启不再发字段请求。未发生新发送的旧预算也保留到备份恢复保护记录。
- 缺工作流时传入原自动行图片次数，查询已有图片调用、结果、生成候选元数据后，只有未发现产物才准入有限补做。次数写在新检查点，原行展示合计不会清零。正式提交未知仍优先阻止 AI 接续。

新脱敏夹具覆盖五种目标形态、ACTIVE/DONE 重连、结果保存/采纳崩溃、缺失与耗尽、HTTP 成功未采纳、孤立图片产物以及旧预算备份保护。自动流程另有两个 94-A/B 入口用例，明确断言零正式提交。所有测试仅使用隔离临时数据和注入响应。

最终相关六文件回归 311/311 通过，TypeScript 检查通过；补充预算/备份回归 39/39 通过（含新增备份前无草稿保护）。沙箱备份用例曾因 Windows realpath EPERM 失败，使用获准宿主 mock 回归复核，不能把环境失败写成程序通过。

## 明确边界
