## 已确认根因

自动上架和七图准备先保存 `FIELDS_STARTED` / `contentPreparation.STARTED`，随后 `ListingAiService.complete` 还会执行来源颜色观察、业务默认值和 Amazon 预览。这些预发步骤失败时字段 POST 为零，但外层永久判为未知。反过来，内部候选/审核调用及两轮预算没有持久操作身份，不能依靠异常文案或 provider requestId 判断重试是否安全。

## 设计

- 新增 schema 18 的 `listing_completion_operations`。每次 complete 使用稳定 UUID，保存草稿、来源与店铺/规则身份、审核策略、已确认草稿 revision/stamp、阶段和最多两轮候选/审核调用。
- 每轮固定候选和审核本地 call UUID、精确 ListingAiContext/hash。准备阶段无发送证据；发送意图在 `AiUsageLedger.reserve` 的同一 SQLite 连接和事务中与 call/usage 一起提交。事务失败三者均回滚。
- 有发送意图却无可信结果时保守 UNKNOWN，禁止自动重新发送。结果按 exact callId/contextHash/调用状态关联复用；采纳按现有 adoption id/from-toRevision/字段指纹恢复；不重置两候选加两审核预算。
- complete 的预览/默认值推进保存确认版本；暂停后的返回不能启动后续请求。来源颜色保持独立 ledger。
- 两个外层保存同一 operationId，读取真实阶段分类。旧 STARTED 缺 journal 继续 UNKNOWN。新操作不能绕开同草稿未结束或恢复保留的已发操作。只读队列证据快照包括 journal。
- 新表加入迁移、重复 JSON 检查、备份结构白名单、记录和历史关联验证。恢复旧备份时合并当前更晚发送事实；缺失结果只留下 no-resend guard，不补造成功。
- 手动 suggest/review 不变；不调整图片请求、候选身份或引入通用重试框架。

## 实现与计数语义

- `repairAttempts` 仍表示自动任务已开始的**逻辑修复操作数**。开始一个新 operation 时递增一次；同 operation 在预览、配额或默认值阶段失败后恢复，不再递增。旧 attempts、能力迁移、颜色与类别额外授权均保留，不清零。
- 字段付费预算由 journal 中两轮固定候选/审核 call UUID 的 `sent` 事实决定，最多两候选加两审核；关闭审核时最多两候选。创建 round 只分配稳定 ID，事务失败不留下 sent/call/usage。恢复沿用原 ID 和剩余预算，不能新建操作绕过任何未完成的同草稿或同来源销售身份操作。已明确完成但仍有待处理项时，外层原有逻辑操作上限继续生效。
- op 的 scope 固定来源事实/素材、销售身份、完整 Schema 指纹、店铺连接代数和文案/类别推断策略版本；可选字段是否被预览激活及其证据由各 round 的精确 context 固定。类别推断策略版本不再随可选字段出现与否改变。
- `applyBusinessDefaults` 与 journal 草稿 checkpoint 在 Amazon 的同一连接事务内提交。预览仅改变校验状态，不改变确认草稿内容指纹。采纳落库但 checkpoint 未落库时，只接受原 adoptionId、from/toRevision、结果/context 引用及字段指纹完全吻合的进展。
- send/call/usage 同事务，result/call/usage/result 引用也同事务。journal 保存使用 revision CAS，旧预览快照不能覆盖另一连接已提交的发送事实。单条/单草稿/同销售身份查询在 SQL 中过滤，不先解析全表。
- 两个调用方传递同一 operationId。自动修复恢复仍先检查任务授权、来源、店铺、销售配方、子执行范围及 submitStarted。暂停后已提交的可信结果保留，恢复授权前不采用；在 adopt 内部 freshness 的 await 与写库之间再次检查 signal。没有可信持久结果的超时、取消或断链始终保留 UNKNOWN。
- 只读队列按 journal 的真实发送阶段判断未知，证据快照包含 journal。未发送的预览失败不会永久 UNKNOWN；真实未知优先于价格或图片规则淘汰。校验失败保持不可执行，不能降级放行。

## 备份与保留期边界

- schema 18 表纳入结构与 record-json 白名单、严格字段/重复键验证、结果与调用/usage/adoption 历史关联校验。旧 schema 夹具同步删除新表后再降级，生产白名单未放宽。
- 恢复时采用当前和备份两边的发送事实并集，不因向前或向后恢复把 sent 改回 false。只有所选备份确实带有、且 call/context 校验通过的结果才可作为证据；当前更晚结果不搬进旧备份冒充成功。缺结果或已完成采纳缺失时转为 `GUARD`，清除结果/采纳引用并保留禁重发事实。合并完成后重新验证 history。
- 恢复防重身份为 mode、sellerId、marketplaceId、listingProgram、productId/productRevision、variantId、销售 SKU 和 recipe hash。它不依赖旧 draftId 或重新连接后的凭据代数。已测试旧快照含同 draft 但无 operationId，以及快照早于 draft、恢复后重建同销售 SKU 的新 draftId；均不能重发。不同模式、项目或销售配方不互相误标未知。
- 保护范围要求仍能识别上述同一来源销售身份。重新导入而获得新的 productId、改变真实来源版本或销售配方，属于新身份；本分支不宣称阻止任意人为改写身份后的请求。旧 STARTED 没有 journal 仍按原规则 UNKNOWN，不据异常文案猜测是否发送。
- 正常草稿保留期清理在同一事务中把有发送记录的 op 转为 `GUARD`、未发送的 op 转为 `RETIRED` 后再删除草稿。无结果引用不会伪装可复用证据，过期历史仍可导出备份；未发送的退休记录不阻断新草稿。
