# 工作区导航

更新日期：2026-10-10。

## 目录分工

| 位置 | 用途 | 管理方式 |
|---|---|---|
| 本项目根目录 | HTC 工作台源码本体及启动入口 | 保持目录名和启动路径 |
| src、tests、scripts、extension、native-host、samples | 源码、测试、工具和合成示例 | Git 管理 |
| docs/maintenance | 脱敏修复与更新记录 | 每次更新随提交维护 |
| docs/version-control | 稳定化计划、归档历史及工作约定 | Git 管理 |
| docs 中其他历史资料、根目录历史需求文件 | 本机业务及历史文档 | 保留原位，按既有忽略规则管理 |
| FTP导入配置 | 本机连接资料 | 不进入版本库 |
| artifacts、.test-data、.cache | 诊断、隔离测试数据和缓存 | 本地保留，清理前核对用途 |
| node_modules、dist*、release | 依赖、构建结果和安装包 | 不进入版本库 |
| 上级工作区的工作记录/HTC版本合并_2026-10-10 | 外出带回的 Git bundle、两份 PDF 和修复说明 | 本地资料归档 |

上级目录中的数据、讨论文档、工具插件、旧交接项目和其他软件保持原位。本轮没有判定其可删除，也未移动未知名称的目录。

## 更新流程

检查状态 → 明确本次范围 → 修改 → 检查差异与相关验证 → 更新维护记录 → 按文件暂存 → commit → 确认工作区状态。

每个完成的更新都创建本地 commit。提交与推送、部署、真实运行分别管理。具体要求见根目录 AGENTS.md。

## 源码与正在运行的程序

`启动 HTC.cmd` 优先启动 `release/HTC-1.0.0-win32-x64/HTC.exe`，只有安装包不存在时才走本地构建入口。因此合并源码不会自动更新正在使用的程序。

本轮仅合并源码并整理文档；现有 dist 和 release 不代表最新源码。后续部署应单独记录源码 commit、验证结果及制品对应关系。

## 历史资料的时效

REPOSITORY_INVENTORY.md 和 repository-files.csv 是初次归档的历史快照，不是当前文件数或哈希清单。稳定化计划的 35 项是验收要求，不是已全部通过的声明。
