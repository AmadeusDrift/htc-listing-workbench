# HTC 2.0.0 目录交付

用户明确要求新版命名为2.0.0，与1.0.0独立分开，并完成release目录交付。

- package.json与package-lock根版本统一2.0.0，程序与采集插件由该版本构建。
- 新版完整程序放入 `release/HTC-2.0.0-win32-x64`，旧 `release/HTC-1.0.0-win32-x64` 保持原位、不覆盖。
- 原 `启动 HTC.cmd` 唯一默认目标改为2.0.0；`启动 HTC UI新版.cmd` 转调原入口。找不到2.0.0时明确提示，不静默打开旧包或源码构建。
- 两版本程序目录独立，沿用既有本地工作区路径；不复制或重置用户数据。新版本可能按既有迁移逻辑升级数据库，保留1.0.0程序不等于保证升级后数据可以降级打开。
- 2.0.0包含10月10日以后已合入的字段规范化、来源事实边界、图片/SKU关联、错误分类、暂停/回读、未知结果保护，以及平面4px控件、统一自动商品列表和全局去装饰线。

交付流程：从干净提交快照构建到新artifacts目录，组包、校验，在隔离数据与入口前断网条件下验收实际EXE，再复制至此前不存在的release/HTC-2.0.0-win32-x64，校验复制后的完整摘要及实际运行。最终源码、结果另补记录；不会自动启动真实业务工作区，不自动push。

旧版启动错误的实际根因尚未复现，本次交付不把目录与版本整理冒充数据库启动故障修复。用户实际数据启动仍需用户打开新版确认。
