# 2026-10-14 Decisions 图片 detail 参数修复

## 根因与边界

类目选择的 Decisions 请求复用了 DeepSeek 视觉内容构造器，其 `detail: original` 不在 Decisions 接口允许的 auto/low/high 中，导致 HTTP 400。已对照官方 https://openrouter.ai/docs/guides/community/multimodal-decisions （2026-10-14）及 API schema核对。

Decisions 专用路径选择 high；原始图片字节、哈希、尺寸及本地来源校验不变，其他调用保持 original。Decisions 发送边界增加枚举与内联图片格式校验，非法值在请求前停止。

## 验证

新增真实 AiService + 合成商品图片 + 假服务契约测试：修复前模拟官方400失败，修复后通过，并逐字节比对发送的原图。未读取凭据或真实库，未请求付费接口。30项相关测试全通过，typecheck与strict模块边界检查通过。Windows 默认沙箱造成 managed-image 路径身份检查失败，使用获准的本机隔离测试执行通过；未降低生产路径校验。

## 接续核对

原有类目流程仅在全部阶段完成后持久化 classification；`classifyProduct` 每次重新走 keywords，`AiService.decideCategory` 无阶段恢复。因此这条400不依赖403许可即可再次进入类目判断，但必须由集成修复继续核对成功关键词复用及未知类目请求防重发，不能把当前参数修复等同完整接续保证。本分支不清历史、不改任务、不解锁UNKNOWN。

## 类目阶段接续补修（同批）

针对用户“不得重发未知请求”的要求补齐类目阶段原有缺口：
- AiCall 增加可选 categoryContext（版本、阶段、包含原图哈希及模型/思考的请求哈希），与调用和费用同事务持久化；完整记录校验支持该字段，无Schema迁移。
- 相同商品修订、输入负载、模型/思考的已成功阶段复用原结果；旧结果须由成功调用拥有且来源哈希相同。成功关键词不会因后续选择400而重发。
- 未解决的类别请求、缺少身份的历史类别请求保守阻断；修改配置不解除未知保护。
- 只有旧版 category_decision 的完整且精确匹配 `state[1] ... image_url.detail ... auto|low|high` 的400回执，在用户显式继续时间晚于失败时，才给一次参数修复尝试。任意其他400、缺回执、新版仍400、超时均不自动补发。
- 一次性修复许可与调用/费用原子记录；发送前及记账事务内校验旧调用快照，避免并发新增调用。
- 恢复旧备份保留修复许可及缺失类目调用的安全身份墓碑，旧备份不得使未知调用重新变成未发送。保留现有原Batch身份回收路径，不把Batch外层错误作为条目拒绝证据。

专项41项通过，新增并发防重发后阶段恢复12项全部通过，typecheck、strict边界通过。原始30项参数修复测试已包含其中。真实请求、真实任务、线上成功率未验证；原始资料绑定和套装件数不属此分支修改范围。

## 最新隔离样本补充：同商品多条相同400

实际只读样本显示同一商品修订存在两条独立的历史 Decisions detail400。现在逐条验证完整回执后，将同一商品/修订/选择阶段的明确参数拒绝合并为一次修正机会，而不是因为数量大于一继续阻断。v2 审计保存全部 priorCallIds，历史调用不改写；成功后整组旧拒绝被同一新成功结果覆盖，刷新/重复继续复用结果。混入任何未知请求或403都不能借用本规则。备份保留v1和v2一次性审计，原有未知身份墓碑继续生效。

新增多400/混合UNKNOWN/多403三项隔离测试；类目阶段15项全部通过，typecheck通过。未对真实样本发请求。
