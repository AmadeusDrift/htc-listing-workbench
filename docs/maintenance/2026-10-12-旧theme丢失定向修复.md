# 2026-10-12 旧主题解析丢失的定向修复

## 原因与授权范围

旧有限字段解析器把带解释的 theme 候选以“仅推断候选可以携带推断理由；已保留其他合格字段”排除。实际只读副本中该 SKU 的 18 条字段结果没有可恢复的 theme 候选；当前完整 Schema 解析器已接受解释，不需要再放宽解析规则。原自动任务字段尝试为 4（原 2 次、旧字段规则额度 1 次、来源颜色额度 1 次），七张图片已完成。

本次只允许符合该历史证据的任务新增 **一个 theme 定向修复操作**。一个操作不等于一次 HTTP 请求：仍沿用每操作最多两轮候选/复核、每缺失步骤最多三次的现有有界恢复，以及原有费用台账。原 4 次不归零，旧策略标记不删除，旧调用、结果、采用记录及七图保留。没有可恢复值时让当前模型重新补主题，不虚构旧值，不重新生图。

## 实现边界

- 资格同时检查原四次额度构成、当前 theme 缺失、相同草稿版本、有效七图来源、旧有限解析上下文、精确错误原因、当前来源/目标/规则/证据一致、全部历史调用/结果/费用身份，以及没有候选或未确认字段操作。相似文案和普通耗尽不会获得额度。
- 新操作单独持久化版本 `legacy-theme-parser/v1`、原结果/调用/上下文、来源工作流、原草稿指纹以及 `fields: ['theme']`；不会复用旧 DONE 操作。操作与 owner 检查点之间中断时复用已建的无发送操作。
- 自动 owner 在发送前持久化额度、尝试 5、FIELDS_STARTED 与操作 ID。费用预留事务中的 markSent 再检查该额度；缺 owner 检查点不发送。
- 所有轮次的请求字段和 repairRequest 均被范围限制，自动和直接采纳均只允许 theme；范围不可由后续保存删除。定向操作跳过普通颜色准备与业务默认写入；DONE 重读不恢复不相关字段。
- theme 完成仍进入原 RECHECK_PENDING 和七图重新授权流程；其他字段错误保留，不能直接变成待提交状态。

## 独立审查补修（P1，后续提交）

审查发现仅限制模型采纳字段还不足以保证 theme-only：普通预览会规范化颜色，普通采纳会清理 Haul 不支持属性。本次采用保守拒绝而非借定向修复顺带改值。

- 将现有 Haul/颜色规范化计划抽成同一纯计算函数，行为不变；资格确认事务在创建/复用定向操作前预测，任何无关规范化均拒绝，未消费额度。
- previewDraft 在进入其 catch 持久化路径前检查，normalizeHaulRecord 内再次于属性赋值前保护。
- adoptFields 在原事务内检查非 theme 属性未改变，并检查将执行的规范化计划；赋值前拒绝，事务内审计等也一并回滚。
- 新增六项 Haul 回归：颜色 Cherry Blossom Pink 与不支持的 fulfillment_availability，分别覆盖资格、直接 preview、直接 adoption；验证草稿字节/审计事件不变、预览与新付费请求为 0。四项直接边界用例在 a5f6e22 上全部失败、补修后全部通过（本地 red/green 日志保留）。
- 相关套件 77/77 通过，TypeScript 通过。实际45新副本重新验证仍能准备同一绑定操作，原六表不变，外部 dispatch 0。

本补修不改 a5f6e22 的历史，不更改原尝试、图片或正式运行数据；全量回归由集成主代理统一执行。
