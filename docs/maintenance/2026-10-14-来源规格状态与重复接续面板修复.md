# 2026-10-14 来源规格状态与重复接续面板修复

## 范围与证据

分支 `fix/source-status-ui` 从 `f78e706` 创建，未操作真实 APP、数据库、Key 或外部服务。

- `buildAutomaticProductGroups` 原先仅从完整详情取数量，即使 `ProductSummary.variantCount` 已存在也显示未完整读取；完整检查明确改为点击触发后，这个提示会误导尚未检查的用户。

## 改动

1. 完整来源详情可用时使用详情数量，否则使用商品摘要数量；未拿到可信数量时区分尚未读取、读取中、实际读取失败。
2. 显式检查成功的数量按任务缓存。任务 revision 使检查证明/明细失效时，备用数量标注“含已读快照”；新摘要优先覆盖该缓存，不能将快照宣传为当前最新数据。
3. 摘要/快照只有数量，不伪造规格列表或未纳入数量。未读取明细提示用户点击“检查当前规则与资料”；失败重试提示也改指向该真实入口。
4. 不恢复周期性全量来源检查，不改变 UNKNOWN 请求/提交保护、自动继续行为、错误分类或真实业务状态。异常系统原因分类由独立后端分支负责；现有历史/本次失败区已在隔离测试验证，未伪造调用日志入口。
