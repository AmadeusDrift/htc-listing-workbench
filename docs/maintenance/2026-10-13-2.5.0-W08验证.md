## 里程碑二：真实 APP Batch 链路与任务授权

- `AiService.batchTasks` 是真实运行对象，main 将它注入 AutomaticListingService；任务按完整一轮 SKU 准备后 flush，不逐 SKU 建一个模拟队列，也没有 sleep 替代远端处理。
- OpenRouter 业务适配器在实际序列化正文后、普通 beforeSend 前进入延迟边界；现有 BatchService 负责真实 `/api/v1/batches` POST 及原 remote ID GET。按任务/阶段/用途/模型/思考/Schema/credential 分组，依赖结果通过领域解析并采用后才进入下一轮。
- BatchOperation 可选 `aiCallId` 保持原 durable callId，旧记录缺省 item.id。逐项 ledger 预占、原 ai_call、completion/field-group sent 同事务；采用沿原 parser，AiResult/call/result checkpoint/Batch adoption 同事务，不重复 reserve。预占的 startedAt 是唯一预算时间身份；费用报告把逐项收据映射回原 callId，不把 Batch 总价和逐项价相加。
- `BatchWaitingError` 透传到任务 WAITING；ImageWorkflow 使用 WAITING_BATCH，保留原内容操作、plan/slot/attempt。当前同进程授权在等待中保留；暂停/取消撤销后只有原远端结果回收，不采用或发布。重启所有 WAITING/QUEUED/RUNNING 自动任务进入 PAUSED，显式继续后按原身份恢复。
- task.save 在同连接事务检查原 revision，TaskPort 仍按原 record_json CAS。回读不能充当新执行授权；原任务授权有效时可继续备货，重启/撤销后不新建步骤。迟到 ACCEPTED 正向测试的合成父任务 checkpoint 现显式保留原 grant，暂停/取消仍检验零下游请求。
