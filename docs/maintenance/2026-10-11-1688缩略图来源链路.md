# 1688 缩略图来源链路

原生 1688 回执已保存 SKU 图片映射，但自动准备仅读取妙手回执，导致图片无法下载；本地 SKU 从多项删至一项后，也可能把其他 SKU 遗留的未绑定图片当作单品通用图。

本次在主进程增加判别来源解析器。原生严格沿 `localVariantId → providerSkuId → snapshot.skuImages → images` 解析，保留回执身份、指纹、原始来源 SKU、图片 ID、URL 与映射依据，不根据颜色文字或文件名推测。不构造伪妙手回执。原生优先 provider-sku-id，每 SKU 最多三个候选，按选中且仍存活 SKU 的图片并集分批（每批最多 20），同一失败 URL 不在本轮重试。同图共用尺码可绑定；同字节不同 URL 仅对本轮新建资产合并新绑定。

来源策略从数据库读取，覆盖 prepare、七图、旧单图、已完成快捷复用、recheck、规则证据、AI 当前引用和发送前检查，不依赖是否配置下载服务。原生空映射或历史多 SKU 缩为单 SKU 不能借通用未绑定图；当前人工确认绑定仍可作为身份依据。无来源回执的人工单品保留旧行为。双来源身份冲突/记录损坏/下载故障为 SYSTEM_REPAIR，确实缺图或缺少确认绑定为 NEEDS_INPUT，不转成规则过滤。

数据库升级至 19，新增 `source_image_provenance` / `source-image-provenance/v1` 追加身份观察。下载字节的哈希、尺寸、MIME、长度、时间与原回执及映射绑定。导入后重新核对版本、回执和实际文件；身份锚与本次新增绑定及图片角色同一 SQLite 事务保存。失败留下未绑定、未锚定的已导入资产，不删除或靠文件名重建。已有同 hash 资产可追加真实下载观察，但不会重新确认或恢复用户撤销的绑定。

历史检查允许手工解绑、角色变化和原 SKU 删除，但仍校验存活 SKU 归属、资产所有权、原回执与原字节。启动检查受管图片路径/目录链接与原字节；备份/恢复验证原图哈希和大小。严格拒绝额外键、重复 JSON 键、重复映射/观察和额外表字段。旧备份没有身份观察时保持为空，不回填旧资产、不改写历史 AI 上下文或哈希。身份锚本身不表示视觉一致性、颜色可信或视觉 PASS。

验证采用合成 SQLite、图片和注入的下载器，无真实业务库、服务商请求、付费调用或构建。新增失败优先测试覆盖精确选择、同图尺码、20→1 孤儿、当前人工绑定、取消/关闭、锚事务失败、保留历史、篡改字节、junction、严格解析与角色兼容；旧下载测试升级为合法持久化妙手回执。首次 realpath/junction 测试受沙箱 EPERM 阻止，提升后验证，未当作程序通过。旧工作流/AI/备份相关 201 项曾通过；最终受影响集合与退出码保存于 `artifacts/1688-thumbnail-implementation-2026-10-11/final-related.*`，修复前失败保存于 `related-before-repair.*`，单项修复保存在 `repair-related.*`。全量回归、独立审查与提交由父任务在冻结后完成；真实 1688 下载及视觉一致性未验收。
