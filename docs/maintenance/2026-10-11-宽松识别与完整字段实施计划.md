# 宽松识别与完整字段实施计划

用户已在连续讨论中批准五点统一实施，本文件记录执行范围，不再重复审批。目标是先跑通商品识别、类目选择、完整字段填写和自动上架，再以真实样本调整规则。

## 实施顺序

1. DeepSeek 思考模式：AiProfile、功能设置输入、持久化和调用记录增加可选 thinking；旧配置默认关闭，界面每项 DeepSeek 功能可开关。公共适配器按照设置发送 thinking.type，开启时分配思考输出预算；回归配置重启、真实请求体和历史记录兼容。
2. 独立来源识别：在 source-image-consistency 的输出与归纳中引入独立观察及来源合并语义。保留历史结果原有解释，避免改变已有记录导致数据库完整性失败。可见颜色、形状等不再限定于系统已有 claims；无法理解的型号是提示，不构成冲突；有清晰图片的新增属性可用于字段填写。来源图片对应关系复用现有采集映射。
3. 完整 Schema 字段路径：listing-ai 上下文提供原始 schema、metaSchema 及完整商品/SKU/图片证据。取消以 CandidateField 白名单作为 AI 字段覆盖边界；生成、校验、写入和后续图片上下文一起支持新字段，不只是把原始 schema 放入 prompt。业务确定值明确传入，AI 返回内容仍须通过 Amazon 原规则验证。
4. 响应恢复：明确格式模板，兼容已知外壳，保留原始输出。针对本地已有 OUTPUT_INVALID 优先离线解析并重新评估；缺失或实质不合法的响应单独提示，不冒充通过，不自动重复付费。扩大/调整诊断保存以覆盖整批失败证据。
5. 综合交付：相关功能测试、必要完整回归、构建、设置交互检查、隔离 EXE 及正式包摘要核验；更新 release 的 2.0.0，保留旧包和 1.0.0。用户自行打开思考模式进行下一轮实际上架，当前任务保持暂停。

## 有意义的验收样例

- 原名为供应商型号、系统没有可见 claims，AI 从已关联图片识别颜色和形状，信息保留且不中断分类。
- 系统与 AI 识别结果数量不同、新增多值观察，合并后可继续；明确颜色矛盾只影响关联操作。
- Amazon 返回白名单外的必填字段，AI 请求能看到完整规则，合法输出可写入，不支持/缺资料时明确指出字段。
- 思考关闭/开启实际请求分别为 disabled/enabled，配置重启后保留，调用记录可追溯，不依赖重新输入密钥。
- 既有已完成成果、数据库、未知调用记录可继续读取；不因策略变化破坏历史数据或重复提交。

每个根因独立分支并提交，串行合入。验证中废弃规则对应测试按新需求调整，历史数据兼容测试保留；避免反复为了旧业务规则而阻止已批准的新行为。
