## R2 审查补修：拒绝优先级、旧备份预算与耗尽提示

已先复现后修复：

- provider 已明确 refusal / tool_calls 时，usage 缺失、null 或 token 类型错误原先会先触发通用 envelope 错误，进入重复请求。现在先确定拒绝/工具调用；合法 usage 仍结算，损坏 usage 保持未知，固定非重试原因不被元数据错误覆盖。标准 finish_reason=tool_calls（不只 stop）与凭据回显也覆盖。持久化诊断保证重启后不重发。
- 旧备份只有 usage ledger 保留、ai_calls 缺失会让同 workflow/context/slot 的 3 次预算变 0。新增 retainImagePlanningAttempts，与 usage merge 共用恢复写事务，在 prepare 和 commit 两次安全合并中都执行。保留规划调用原身份/上下文/request hash/usage；已有相同 id 的身份冲突拒绝恢复。旧成功调用若结果不在所选备份，仅保留 FAILED/INTERRUPTED 的已消费预算标记，不导入该结果为事实或生成授权。
- 规划达到 3 次现在有固定可见提示“图片规划已达到 3 次尝试，已保留原图和请求记录”，并携带 IMAGE_PLAN_ATTEMPTS_EXHAUSTED 诊断标识，明确区分图片生成次数。第 3 次错误的原始调用细因保留；后续发送前预算拦截不新增 call 或费用。
