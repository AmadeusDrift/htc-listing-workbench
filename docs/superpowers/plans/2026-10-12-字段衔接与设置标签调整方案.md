# 字段衔接与设置标签调整方案（讨论草稿，未确定）

> **For agentic workers:** 当前先完成核对与讨论，不直接执行下列实施条目。用户明确指出方案尚未确定。后续方案确认后实施时使用 executing-plans；下列复选框为拟议步骤，不是执行授权。

前置工作：按[交接草稿第0节](../../交接文档_2026-10-12.md)逐项核对原问题，报告证据、仍不确定之处和可选处理。不能用整理好文档代替回答用户问题。尤其预检范围、图片字段接线和标签等待根因尚未确定，下述实现顺序也只是建议。

**Goal:** 恢复用户已确认的业务填报规则，减少本地自设阻断，使字段、图片、平台反馈和标签状态衔接一致。

**Architecture:** 沿用现有 Electron、任务和调用账本，分开处理确定性业务填报、AI 语义填写、图片真实产物和平台反馈。对格式、业务缺项、显式冲突分别处置；保留未知请求保护和已有成果，不新建复杂审批系统。

**Tech Stack:** TypeScript、Electron/React、SQLite、现有 Amazon/AI/图片托管适配器。

## 1. 用户问题逐项对应

| 用户问题 | 当前证据与待核对项 | 拟议调整方向（未定稿） |
|---|---|---|
| 标签状态到底是什么问题 | 已有历史 PDF READY，但任务仍 WAITING/LABELS；不是已证实标签生成失败 | 查状态推进/重启恢复，只修标签完成衔接 |
| 前面放宽了，后面仍不接受？ | R01/R02 修响应解析与恢复，R03 修旧策略；独立的 fact-authority 门槛仍阻断 | 补齐业务默认到验证/采纳/提交的链路，不把旧约定变成缺资料 |
| AI 填的是否 Amazon 字段 | 本轮 AI 返回三个属性，采纳后被本地 Haul 规则拒；这些字段是否在对应请求完整 schema、适用分支以及本地禁用依据，尚需逐项对照 | 保存 schema→输入→候选→草稿→平台反馈对照，不先假定所有禁用均正确 |
| 本地预检是否多余 | 已确认“规则先填、平台预览反馈补填”；最新用户要求减少本地拒绝 | 建议保留请求可发送性检查，语义/业务缺项交平台预览；不把该建议当已批准取消所有检查 |
| “已确认资料”是什么 | 当前只认特定 facts 状态和有效 SKU 回执，规则默认不算；导致配置值存在仍不能走通 | 不再以“扩大AI证据”作为唯一修法；确定业务值有独立、明确的填报权限 |
| 制造商/产地/尺寸重量 | 既有映射与默认已确认，不再询问用户 | 按固定认知恢复；实际值优先、回退明确标记 |
| 本地恢复是否失败 | 17 份实际恢复成功，后面遇到另一道阻断；2 份尚未运行 | 恢复结果继续复用，不重发原请求、不抹掉历史失败 |
| 图片字段再查 | 尚未逐 SKU 完整核对七图资产到平台字段的映射 | 单独核对 URL 与 schema 结构，不能由模型编链接 |
| 思考开关报错 | `ai-ipc.ts` 保存后又用不含 thinking 的 keys 校验，服务支持但 IPC 拒绝 | 修入口兼容及回传，验证保存、重启和请求参数 |
| 旧资料/业务/未知请求问题 | 已登记 R04–R10 等，并保留本次95项分组 | 留在交接，不在前三个核心链路修复中混改全部 |
| 商品淘汰与异常显示 | 规则淘汰移出待上架，异常和缺资料保留、原因清楚 | 单独做分类与 UI，不能把所有FAILED隐藏 |

## 2. 建议处理顺序

先修 A 思考设置的小阻断；B 恢复业务默认与 C 平台反馈衔接为主线；D 图片字段、E 标签状态分别完成；F 分类/UI 最后整合。每项从最新集成分支创建独立修复分支，定向复现、最小修改、必要回归、本地提交、合并。真实批次继续暂停，完成后统一更新正式2.0.0，再进行用户约定的实测。

### A. 思考开关：修保存入口，不重做模型接入

入口：`src/main/ai-ipc.ts`、`src/main/ai/service.ts`、`src/renderer/credential-status.ts`、`src/renderer/AiConnectionSettings.tsx`；新测试建议 `tests/ai-settings-ipc.test.ts`，现有 `tests/ai-connections.test.ts`、`tests/ai-service.test.ts`。

- [ ] 用实际 IPC handler + 合成配置复现：传 thinking:true，保存服务已变更却返回 INVALID_INPUT。
- [ ] 在 mutation 前完成一致的输入解析，允许可选 thinking，避免保存后第二次旧格式拒绝；返回真实保存状态。
- [ ] 检验生成/复核独立开关、模型切换不重置思考值、不要求重新填密钥；非法输入不能先写入再报错。
- [ ] 重开设置/重启仍显示保存值；模拟供应商请求确认 thinking 和用量预算对应，不向真实服务额外发请求。
- [ ] 记录失败复现与通过结果，提交。开启真实模式的质量/速度另在用户实测记录，不能用保存成功代替效果验证。

### B. 恢复业务规则，而不是让用户补旧配置

**2026-10-12 本项方向已获用户明确认可，当前仅登记：**规则确定的字段由程序自动填写并认可业务配置依据，不再额外要求人工确认；其他商品属性单独判断。真实值优先、缺失按已确认默认值填报，默认值不进入图片实测说明。认可本项不代表整份方案定稿或本次开始实施。

入口：`src/shared/listing-rules.ts`、`src/main/amazon/business-rules.ts`、`src/main/amazon/fact-authority.ts`、`src/main/amazon/service.ts`；测试建议 `tests/business-default-authority.test.ts`，并复用现有业务/字段回归。

- [ ] 以 U2、U6、U8 和真实值/缺值两类合成样本复现：已有配置却未填、填后被事实门槛拒绝。
- [ ] 为**本来就由业务配置决定**的字段提供规则依据：Generic、制造商映射、CN、适用默认声明、尺寸重量回退、标价与SKU派生。继续保留原始值、规则版本、作用店铺/SKU。
- [ ] 已知真实尺寸/包装重量优先，缺项按配置补；包装100g不冒充净重、不按件数乘；默认值不进入图片上下文。不能简单删除所有 fact-authority 检查。
- [ ] 按字段来源区分：规则确定值不再要求额外来源确认；来源/AI观察的商品属性按合并结果使用；真实相反内容保留具体冲突；证书文件等无资料时不编造。
- [ ] 同步草稿创建、已有草稿应用规则、AI采纳后、图片前检查、预览/提交、重启恢复，避免前一层接受后一层又拒绝。旧草稿定向修，不清库或重建全批。
- [ ] 验收同一条样本从填报到预览入口不再出现固定字段“缺事实”；真实值保留、默认不会进入生图文字、旧调用与图片不变。提交并记录未测的真实发布范围。

### C. 减少本地预检，并统一字段适用性

**2026-10-12 已确认的局部处理，当前只登记：**上述三个Haul官方不支持字段若已被填写，自动从待发送草稿中移除，保留其他有效字段，记录清理原因并继续；不能以这三个字段存在为由阻断整件商品或任务。无需为删除再次调用AI或要求用户操作。保留原响应和历史，不清除其他独立错误。后续实现应覆盖新候选、已有草稿及重复继续，避免每次重新写入又报错；其他预检取舍仍待讨论。

入口：`src/main/amazon/service.ts`、`src/main/amazon/listing-program.ts`、`src/main/listing-ai/full-schema.ts`、`src/main/listing-ai/service.ts`、`src/main/ai/listing-adapters.ts`、`src/main/automatic-listing/service.ts`。

- [ ] 先对48/49的完整schema、请求、候选、采纳及错误做字段对照，查三个属性是否适用，必要时核对Amazon官方当前资料。不能把“schema里出现”直接等同“当前Haul情景必填”，也不能仅凭本地硬编码证明禁用合理。
- [ ] 列出现有本地ERROR：请求损坏/身份缺失、可交平台判断的业务字段、未知提交保护。给用户审阅需保留的最小门槛，不新增审批UI。
- [ ] 建议预览入口只阻止无法发送的结构、目标/身份缺失等错误；能构造请求的缺项交 Amazon VALIDATION_PREVIEW。平台返回缺项/枚举/条件问题后定向补；限流/权限错误不让AI改商品资料。
- [ ] 全量schema保留；将明确且经核对的项目规则同时接入AI输入、候选采纳和提交，删除“先采纳后才发现本地禁止”的矛盾路径。程序管理字段单独合并，但不得靠固定名单裁掉其他商品属性。
- [ ] 保留合格字段和已完成图片；每次修改使对应旧预览失效；不固定增加独立模型复核。修复次数沿用已有有界机制，不反复创建新operation消除预算。
- [ ] 以实际错误脱敏样本验证候选局部错误、补填、平台预览、已成功子体保护。明确INVALID与未知提交分流，不重复提交未知结果。

**需审阅的设计选择：**本方案推荐“轻量本地检查＋平台验证预览”，而非先进行真实发布再试错。用户已要求减少本地门槛，但尚未确认所有本地检查删除的具体范围。

### D. 图片字段：资产到平台实际结构的核对
